# SKY-L0127: a value holding a function is used more than once

A binding (a `let`, a function parameter, or a `case` arm variable) whose type
embeds a function — a bare function value, or a function held inside a
`Maybe`/`Result`/user-union payload — was used more than once in a
value-consuming position.

The Rust backend renders a function value as `Box<dyn Fn(..) -> R + Send +
'static>`, which is not `Clone`. Reading it once moves it; a second read of
the same binding would move an already-moved value (`cargo`'s E0382). Calling
the function directly (`f x`) does **not** consume it — `Box<dyn Fn>` calls
borrow via `Fn::call(&self, ..)` — so a function value may be *called* any
number of times. It is a second **non-call** use (passed to another function,
stored again, returned again) that is rejected here.

## How to fix

**Re-construct the value at each use site**, if reconstructing is cheap:

```sky
-- before (SKY-L0127 — `mf` used twice)
let mf = Just (\x -> x + 1) in
( consume mf, consume mf )

-- after (construct twice)
( consume (Just (\x -> x + 1)), consume (Just (\x -> x + 1)) )
```

**Restructure to a single linear use**, threading the value through instead of
branching:

```sky
-- before
let mf = Just inc in
case pickOne of
    A -> consume mf
    B -> consume mf

-- after
case pickOne of
    A -> consume (Just inc)
    B -> consume (Just inc)
```

**Call the function instead of forwarding it**, when the goal is just to apply
it — calling is unlimited:

```sky
-- fine, no SKY-L0127: `f` is CALLED twice, never forwarded
case Just (\x -> x + 1) of
    Just f -> f 1 + f 2
```

## Why this happens

A function value has no sound `Clone` impl in the Rust backend (`Box<dyn Fn>`
cannot be cloned in general — an arbitrary captured closure has no defined
duplication). A general "clone what can be cloned, diagnose what can't" pass
is planned (tracked as an extension of the existing non-Clone-capture
analysis, [SKY-L0126](SKY-L0126.md)); until it lands, more than one
non-call use of a function-carrying binding is rejected here rather than
emitting Rust that fails to build.

## Types affected

- Function types (`a -> b`), including curried ones
- `Maybe (a -> b)`, `Result e (a -> b)`, or a user union payload holding one
