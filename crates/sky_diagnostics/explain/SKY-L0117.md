# SKY-L0117: Float is not a valid Set element or Dict key on the Rust backend

Sky's `Float` is a `comparable` value, so the type checker accepts a
`Set Float` or a `Dict Float v` — the typing follows Sky. The Rust backend,
however, has no sound representation for such a collection: `Set a` is backed by
`BTreeSet<a>` and `Dict k v` by `HashMap<k, v>`, and Rust's `f64` implements
neither `Ord` (a NaN has no place in a total order) nor `Hash` / `Eq` (NaN is
not even equal to itself). Emitting `BTreeSet<f64>` / `HashMap<f64, _>` would
produce Rust that does not compile, so the case is rejected here at lowering
with this dedicated diagnostic instead.

This is a **Divergence from Sky**, rationale: Rust backend capability. It is a
deliberate, permanent property of the standard-library backing — not an
unimplemented feature.

## Use a totally-ordered, hashable element / key

`Int`, `Char`, `String`, and `Bool` are all `Ord` and `Hash` in Rust, so they
make sound `Set` elements and `Dict` keys:

```sky
ids : Set Int
ids =
    Set.fromList [ 1, 2, 3 ]
```

```sky
prices : Dict String Int
prices =
    Dict.insert "apple" 120 Dict.empty
```

## Carry the Float as a value, key on something else

When you need `Float` data in a keyed collection, key on a stable identifier and
store the `Float` in the value position:

```sky
readings : Dict String Float
readings =
    Dict.insert "sensor-a" 21.5 Dict.empty
```

If you genuinely need set membership over floating-point data, quantise it to an
`Int` (for example, cents instead of a fractional currency amount, or a rounded
bucket index) before inserting.

Full `Float`-keyed collection support via a total-order wrapper (e.g. ordered
floats that treat NaN as a designated minimum) is a future enhancement for this
backend.
