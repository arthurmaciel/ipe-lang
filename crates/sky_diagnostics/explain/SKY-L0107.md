# SKY-L0107: function value in a record field not supported yet

You put a function value into a record field — a lambda, or a function
named or returned as a value, assigned to a field of a record. Sky can
parse and type-check this, but the Rust backend can't store a function in
a record field yet.

A function value compiles to a boxed closure, and a record compiles to a
struct that derives `Clone`, `Debug`, and `PartialEq` — none of which a
boxed function satisfies. So a record carrying a function field would emit
Rust that does not build. Rather than hand you broken output, the compiler
stops here.

This is the one remaining first-class-function gap. Everything else works:
you can pass a function as an argument, return a function, and bind a
function to a `let`. Only a record *field* can't hold one yet.

`[feature: first-class-functions]`

Putting a function in a record field trips this:

```sky
handlers : { onClick : Int -> Int, label : String }
handlers =
    { onClick = \n -> n + 1, label = "inc" }
```

So does naming or returning a function into a field:

```sky
config : { step : Int -> Int }
config =
    { step = increment }
```

Bind the function to a `let` (or pass it as an argument) instead, and keep
plain values in the record:

```sky
apply : (Int -> Int) -> Int -> Int
apply f x =
    f x

result : Int
result =
    let step = increment in
    apply step 10
```

This is a current limitation, not a wrong move on your part. If storing
functions in records matters for your work, please nudge us at
https://codeberg.org/sky-lang/sky-rust/issues.
