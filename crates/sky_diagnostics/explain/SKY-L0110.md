# SKY-L0110: partial or over-application not supported yet

You called a function with a number of arguments that differs from the
arity its definition declares. Sky understands what you mean, but this
version of the Rust compiler lowers only *saturated* calls — every
function call must pass exactly as many arguments as the function takes.

Two shapes hit this limit. **Partial application** passes fewer
arguments than the function declares, producing a new function that
waits for the rest. **Over-application** passes more arguments than the
function declares, calling the result of the first call with the extra
arguments. Both are valid Sky; they are simply features the Rust
backend has not reached yet.

The compiler refuses rather than emit a call it cannot lower soundly:
silently dropping or fabricating arguments would produce Rust that
either fails to compile or computes the wrong answer. Until partial and
over-application land, give every call the exact argument count its
definition declares — wrap the missing arguments in an explicit lambda.

`[feature: partial-over-application]`

Partial application — `add` takes two arguments but gets one:

```sky
add : Int -> Int -> Int
add a b = a + b

addTwo : Int -> Int
addTwo = add 2
```

Wrap the gap in an explicit lambda, which passes both arguments at once:

```sky
add : Int -> Int -> Int
add a b = a + b

addTwo : Int -> Int
addTwo = \n -> add 2 n
```

Over-application — `constant` takes one argument but gets two:

```sky
constant : Int -> Int
constant x = x

oops : Int
oops = constant 1 2
```

This is a current limitation of the Sky Rust compiler, not a problem
with your code. If partial or over-application is important to your
project, please tell us at
https://codeberg.org/sky-lang/sky-rust/issues.
