# SKY-L0114: function value in a constructor payload not supported yet

`Ok`/`Just` and other constructor-payload function values are supported —
this diagnostic now fires only for two narrower residual shapes: a function
inside a `List`/`Dict`/`Set` payload element, and a CURRIED (2-or-more
argument) function flowing through `Maybe.andMap` / `Result.andMap`.

## What works today

Storing a function in a built-in `Maybe`/`Result`, or in a user union's
payload — declared or laundered through a type variable — compiles and
runs. The runtime `SkyMaybe`/`SkyResult` enums derive `Clone`/`Debug`/
`PartialEq` generically bounded on their payload; a user enum's derives are
dropped automatically when a field is not derivable (its string rendering
falls back to `<fn>`).

```sky
type Retryish e = RetryAlways | RetryWhen (e -> Bool)

shouldRetry : Retryish Int -> Int -> Bool
shouldRetry r e =
    case r of
        RetryAlways -> True
        RetryWhen f -> f e

main = println (if shouldRetry (RetryWhen (\n -> n > 5)) 10 then "retry" else "stop")
```

```sky
main =
    println (String.fromInt
        (Result.withDefault 0 (Ok (\x -> x + 1) |> Result.andMap (Ok 2))))
    -- prints 3
```

Calling an extracted function value more than once is fine — a `Box<dyn Fn>`
call borrows, never moves:

```sky
main =
    println (String.fromInt
        (case Just (\x -> x + 1) of
            Just f -> f 1 + f 2     -- 5, both calls are sound
            Nothing -> 0))
```

## What still needs curried-payload support (Stage 2)

`Maybe.andMap` / `Result.andMap` apply the wrapped function to exactly ONE
argument per application. A CURRIED payload (`\a b -> …`) instantiates the
`andMap` result to another function — the applicative chain has not reached
a fully-applied value, and finishing it needs nested-closure lowering not
implemented yet:

```sky
main =
    println (String.fromInt (Maybe.withDefault 0
        (Just (\a b -> a + b)
            |> Maybe.andMap (Just 1)
            |> Maybe.andMap (Just 2))))   -- not yet: SKY-L0114
```

## Collections of functions still need support

A function inside a `List`/`Dict`/`Set` element is still rejected — the
emitted `Vec<T>`/`HashMap<K,V>`/`BTreeSet<T>` element type is a real Rust
generic instantiation, and several collection kernels (e.g. `Dict.get`)
`.clone()` their element, which a `Box<dyn Fn>` cannot satisfy:

```sky
type Box a = Mk a

main =
    println "unreachable"
    -- `Mk [\x -> x, \x -> x + 1]` (a List of functions in a payload): not yet
```

See also [SKY-L0127](SKY-L0127.md) — using the SAME fn-carrying value more
than once (a residual reuse gate, not a payload-construction gate).

`[feature: ctor-payload-function]`

This is a current limitation of the Sky Rust compiler, not a problem with
your code. If either residual shape matters to your project, please tell us
at https://codeberg.org/sky-lang/sky-rust/issues.
