# SKY-L0114: function value in a constructor payload not supported yet

A data constructor was given a function value as one of its payload fields,
in one of the two shapes that remain unsound to lower today: a **collection**
of functions (`List` / `Dict` / `Set`) or a **curried (two-or-more-argument)
payload flowing into `Maybe.andMap` / `Result.andMap`**.

Storing a function in `Ok` / `Just` (or a user union's constructor) is now
**supported** — `Ok f` / `Just f` construct the runtime's `SkyResult` /
`SkyMaybe` enums, whose derives are generic-bounded, and a user union's
derives are automatically dropped when a payload embeds a function. This page
used to describe that as the limitation; it is fixed (#90). What is left
gated is narrower:

## Collections of functions — still gated

`List (a -> b)`, `Dict k (a -> b)`, and `Set (a -> b)` are not yet supported:
several collection kernels (`DictGet`, `ListMap`, …) blanket-`.clone()` their
element, and a `Box<dyn Fn>` element is not `Clone`.

```sky
handlers =
    [ (\n -> n + 1), (\n -> n * 2) ]   -- List (Int -> Int): not yet

main = println "unreachable"
```

## Curried `andMap` payload — still gated

`Maybe.andMap` / `Result.andMap` apply their wrapped function to exactly ONE
argument. A payload function that takes two or more arguments leaves a
residual function after that one application — there is no sound lowering
for that shape yet (a full curried-applicative chain is tracked separately).
This is primarily a type error (`SKY-T0014` — see that page's `andMap`
section) raised before lowering ever runs; this lowering-time check is a
defense-in-depth backstop behind it, so either code may be the one you see:

```sky
add3 a b c =
    a + b + c

main =
    Just add3
        |> Maybe.andMap (Just 1)   -- payload is `Int -> Int -> Int`: not yet
        |> Maybe.withDefault 0
```

A single-argument payload through `andMap` works, and so does storing any
other function value in `Ok` / `Just` / a user union's payload:

```sky
inc n =
    n + 1

main =
    Just inc
        |> Maybe.andMap (Just 41)
        |> Maybe.withDefault 0
        |> String.fromInt
        |> println   -- 42
```

A declared function-typed payload also works today, including through an
extracted-and-called-twice payload:

```sky
type Retryish e
    = RetryAlways
    | RetryWhen (e -> Bool)

alwaysTrue : Retryish Int
alwaysTrue =
    RetryWhen (\_ -> True)

main =
    case alwaysTrue of
        RetryWhen f ->
            println (if f 1 && f 2 then "retry" else "stop")

        RetryAlways ->
            println "retry"
```

`[feature: ctor-payload-function]`

This is a current limitation of the Sky Rust compiler, not a problem with
your code. If a function-carrying collection or a curried `andMap` chain
matters to your project, please tell us at
https://codeberg.org/sky-lang/sky-rust/issues.
