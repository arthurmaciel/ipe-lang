# SKY-L0114: function value in a constructor payload not supported yet

A data constructor was given a function value as one of its payload fields
— either declared that way (`type Box = Mk (Int -> Int)`) or laundered
there through a type variable (`type Box a = Mk a`, applied as
`Mk (\n -> n + 1)`). The generated Rust enum derives `Clone`, `Debug`,
`PartialEq`, and a string-rendering impl, and a stored function value
(`Box<dyn Fn(..) -> _>`) satisfies none of those — so accepting it would
emit Rust that does not compile.

This is the constructor-payload sibling of SKY-L0107 (a function value in a
*record* field). Storing a function in a plain `let` works — no derive is
involved there; storing one inside a constructor payload is the part that
is not supported yet.

## Declared function payload

A constructor field whose declared type is a function is rejected at the
type declaration:

```sky
type Box = Mk (Int -> Int)      -- function-typed payload: not yet

main = println "unreachable"
```

## Function laundered through a type variable

A generic constructor instantiated to a function at the use site is
rejected at the construction site:

```sky
type Box a = Mk a

unwrap : Box (Int -> Int) -> Int
unwrap b =
    case b of
        Mk f -> f 1

main = println (String.fromInt (unwrap (Mk (\n -> n + 1))))   -- not yet
```

## Storing data in a payload works today

A constructor payload that carries data — not a function — compiles and
runs:

```sky
type Box a = Mk a

unwrap : Box Int -> Int
unwrap b =
    case b of
        Mk n -> n

main = println (String.fromInt (unwrap (Mk 41)))    -- OK: prints 41
```

`[feature: ctor-payload-function]`

This is a current limitation of the Sky Rust compiler, not a problem with
your code. If a function-carrying constructor payload matters to your
project, please tell us at
https://codeberg.org/sky-lang/sky-rust/issues.
