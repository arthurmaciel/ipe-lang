# SKY-L0124: `Live.app` routes list is non-empty but Model has no `page` field

`Live.app` supports two modes:

* **Non-routed** — no `page` field on the Model; `routes` and `notFound` are
  structurally required fields but are not forwarded to the runtime.
* **Routed** — the Model has a `page : Page` field; the runtime calls
  `live_app_routed` and uses `routes` / `notFound` to dispatch incoming URLs.

The compiler detects which mode to use by looking for a `page` field on the
Model type (recovered from the `view` function's first parameter). When the
Model has no `page` field but `routes` is a non-empty list, the routes would
be silently ignored — all URLs serve the same non-routed app.

To use routing, add a `page` field to your Model:

```sky
type Page = HomePage | AboutPage | BlogPage String

type alias Model =
    { page : Page
    , ...
    }

-- Now `routes` is forwarded to the runtime.
main =
    Live.app
        { init = init
        , update = update
        , view = view
        , subscriptions = subscriptions
        , routes =
            [ route "/" HomePage
            , route "/about" AboutPage
            , route "/blog/:slug" BlogPage
            ]
        , notFound = HomePage
        }
```

If you do not need routing, use an empty list for `routes`:

```sky
main =
    Live.app
        { init = init
        , update = update
        , view = view
        , subscriptions = subscriptions
        , routes = []
        , notFound = HomePage
        }
```

The failing case — a non-empty `routes` with no `page` field — looks like:

```sky
-- ✘ routes is non-empty but Model has no `page` field.
type alias Model = { count : Int }

main =
    Live.app
        { ...
        , routes = [ route "/" HomePage ]  -- <-- triggers SKY-L0124
        }
```
