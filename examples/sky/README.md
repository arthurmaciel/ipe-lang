# `examples/sky/` — upstream Sky examples, ported to Ipê

The real upstream Sky examples ([`anzellai/sky`](https://github.com/anzellai/sky)),
mirrored here and ported to Ipê so you can build and run them directly. Two
committed trees hold the result, plus a small tracked control surface that
drives the port.

## Run one

The ports are committed and ready to run:

```sh
cd examples/sky/ipe/00-standard-libs
ipe run
```

Every directory under `examples/sky/ipe/<name>/` is a self-contained Ipê project
(`ipe.toml` + `src/`). Build one with `ipe build`, run it with `ipe run`.

## The two trees

| tree | what it is |
| --- | --- |
| `original/<name>/` | the raw upstream Sky source, verbatim (`.sky`, `sky.toml`) — for reference and diffing |
| `ipe/<name>/` | the runnable Ipê port: `original/` with the Sky→Ipê transform + any per-example edits applied |

Both are regenerated by `tools/scripts/regen-sky-examples.sh`, which fetches the
current upstream from `anzellai/sky`. CI runs it regularly and lands any refresh
as a pull request, so the committed ports track upstream. To refresh locally:

```sh
tools/scripts/regen-sky-examples.sh          # rewrite original/ + ipe/ from upstream
tools/scripts/regen-sky-examples.sh --check  # CI gate: fail if committed trees are stale
```

## Tracked control surface

| file | purpose |
| --- | --- |
| `manifest.toml` | which upstream examples are in scope + which import Go (out of Rust scope) |
| `rename-map.tsv` | the shared Sky→Ipê token rewrite, applied to every example |
| `ipe-edits/<name>.edits` | OPTIONAL per-example content-anchored edits (absent = none) |
| `ATTRIBUTION.md` | upstream provenance + license |
| `README.md` | this file |

## The transform — two ordered steps

`tools/scripts/lib/mirror.sh` derives each `ipe/<name>/` port from its `original/<name>/`:

1. **`rename-map.tsv`** (via
   [`../../tools/scripts/lib/sky-to-ipe-transform.py`](../../tools/scripts/lib/sky-to-ipe-transform.py))
   — the shared, drift-resistant token rewrite: `Sky.Core.*` / `Sky.Http.*` /
   `Sky.Ffi` / `Sky.Test` / `Std.*` → `Ipe.*`, plus the `.sky` → `.ipe`
   source-extension rename and the `sky.toml` → `ipe.toml` `entry` key. It
   rewrites CODE only — never a string literal or comment — and applies to every
   example.
2. **`ipe-edits/<name>.edits`** — an OPTIONAL per-example semantic delta for what
   the token rewrite cannot express (a Go-FFI reimplementation, a stricter Ipê
   type signature, an env-var rename). Each edit is a `find`/`replace` anchored on
   the **exact source text, never a line number**, so it survives the line shifts
   upstream makes between releases. An edit whose `find` text no longer occurs
   fails loud (a RED sweep row), signalling a real upstream change to review.

### Why anchored edits, not line-numbered patches

A unified diff rejects on any shifted context line, and upstream makes exactly
those small edits between releases — which silently rots the patch. Both the
token rewrite and the per-example edits are content-anchored instead, so a port
only needs attention when the *actual text it targets* changes. See
[`ipe-edits/README.md`](ipe-edits/README.md) for the edit-file format.

## How the sweep uses this dir

`tools/scripts/examples-sweep.sh` regenerates the trees, then BUILD (`ipe build` +
`cargo build`) and RUN (headless, per shape) each in-scope `ipe/<name>/` port.
`lib/examples.sh` derives the shape + Go-FFI scope exactly as for the first-party
`examples/NN-*` set. There is **no** Go build and **no** cross-compiler
comparison: the sweep proves that OUR compiler builds and runs the real (ported)
upstream examples.

## Go-FFI scope

The upstream set includes Go-package examples (`08-notes-app`, `11-fyne-stopwatch`,
`13-skyshop`, and the FFI composites). The `is_out_of_scope` Go-FFI filter
(`lib/examples.sh`) excludes those from the Rust build set — a Go-package import
resolving to neither an Ipê stdlib module nor a local project `.ipe` file marks
the example out of scope. They are listed in `manifest.toml` with `go_ffi = true`
so the sweep knows they exist and does not FAIL LOUD, but never tries to build
them.

`13-skyshop` has a first-class Ipê-native rebuild on the shim-free auto-FFI (real
`firestore` / `rs-firebase-admin-sdk` / `async-stripe` crates). Because it is a
structural rebuild, not a token transform of the upstream, it ships as a
**whole-port override** — `examples/sky/ipe-overrides/13-skyshop/` becomes the
`ipe/` port verbatim (see [`ipe-overrides/README.md`](ipe-overrides/README.md)).
