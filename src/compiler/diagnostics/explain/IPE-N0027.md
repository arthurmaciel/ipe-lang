# IPE-N0027: duplicate import qualifier

Two `import` statements register the same qualifier — an explicit `as Alias`, or two module paths that share the same last segment — against two DIFFERENT modules. Without a check, the second import would silently win and every use of the qualifier would resolve against it, with the first import's members becoming unreachable and no diagnostic ever firing.

Two modules both default to the qualifier `Utils`:

```ipe ipe:skip
module Main exposing (main)
import App.Utils
import Lib.Utils

main = println (Utils.format "hi")
```

`App.Utils` and `Lib.Utils` both default their qualifier to `Utils` (the last path segment). Before this check, `Utils.format` would silently resolve to whichever import came last in the file — with no way to tell which one you're actually calling.

The same collision can happen with an explicit alias:

```ipe ipe:skip
module Main exposing (main)
import App.Http as Http
import Ipe.Core.Http as Http

main = println "hi"
```

To fix this, give one import its own qualifier — either an explicit `as Alias`, or by adjusting which segment it defaults to:

```ipe ipe:skip
module Main exposing (main)
import App.Utils as AppUtils
import Lib.Utils

main = println (AppUtils.format "hi")
```

Re-importing the SAME module under the same qualifier (for example, via a diamond dependency where two of your own imports both resolve to the identical dep module) is not an error — only a clash between two DIFFERENT modules claiming one qualifier is rejected.
