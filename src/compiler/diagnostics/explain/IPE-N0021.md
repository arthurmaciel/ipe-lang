# IPE-N0021: import cycle

Two or more modules import each other, forming a cycle. Sky modules must form a directed acyclic graph so that each module can be compiled using only already-compiled dependencies.

A direct cycle between two modules:

```sky
-- src/A.sky
module A exposing (f)
import B
f = B.g
```

```sky
-- src/B.sky
module B exposing (g)
import A
g = A.f
```

Module `A` imports `B`, and `B` imports `A`. This cycle makes it impossible to determine which module to canonicalise first. The error message lists the cycle path: `A → B → A`.

A longer cycle:

```sky
-- src/Models.sky
module Models exposing (User)
import Persistence
```

```sky
-- src/Persistence.sky
module Persistence exposing (save)
import Validation
```

```sky
-- src/Validation.sky
module Validation exposing (validate)
import Models
```

The path is `Models → Persistence → Validation → Models`.

To break the cycle, extract the shared types into a third module that none of the cyclic modules depends on:

```sky
-- src/Types.sky
module Types exposing (User)
type User = User { name : String, age : Int }
```

Then both `Models` and `Validation` import `Types` instead of each other.
