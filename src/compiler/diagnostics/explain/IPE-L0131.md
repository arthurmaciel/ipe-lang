# IPE-L0131: this row-polymorphic record annotation is not yet emittable

A function was annotated with a **row-polymorphic** record type — a record type
that names a few required fields and leaves the rest open with a row variable —
in a position the backend cannot yet turn into Rust.

```ipe
-- `r` is the row variable: "any record that has AT LEAST a `name` field"
getName : { r | name : String } -> String
getName rec =
    rec.name
```

The type `{ r | name : String }` reads as: "a record carrying a `name : String`
field, plus any other fields, which the variable `r` stands in for." A record is
a small bundle of named values, like `{ name = "Ada", age = 36 }`. Row
polymorphism lets one function accept every record that has the fields it needs,
no matter what extra fields ride along.

A row-polymorphic annotation with a **single required field in an argument
position** — like `getName` above — is accepted and compiles: the backend erases
the open row into a Rust generic bounded by a per-field witness trait, and the
Rust compiler generates one specialised copy per record shape it is called with.

This diagnostic fires for the row-polymorphic forms that **do not yet** have a
backend emission:

- an open row with **more than one required field** (`{ r | name : String, age : Int }`);
- an open row in **return position** (`touch : { r | n : T } -> { r | n : T }`);
- an open row **nested** inside another type — under a `List`, a `Maybe`, a
  tuple, or another record (`List { r | name : String }`).

## How to fix

**Give the function a closed record type** that lists every field the callers
actually pass. A closed type has no row variable:

```ipe
-- accepted: a closed record type — the exact field set is known
describe : { name : String, age : Int } -> String
describe rec =
    rec.name
```

**Or drop the annotation** and let the compiler infer the type. Without a
signature, the field access `rec.name` still works, and the compiler pins the
parameter to whatever concrete record you pass at the one call site:

```ipe
-- accepted: no signature; the compiler infers a concrete record shape
describe rec =
    rec.name
```

**Or, for the multi-field argument case,** each required field is still read
through a plain accessor, so an unannotated helper often already does what you
need at a single call shape.

## Why this happens

Ipe's Rust backend represents each closed record shape as a dedicated `struct`,
keyed by its exact, sorted field set. A supported single-field argument row is
lowered instead to a generic bounded by a synthesised field-witness trait, so
the field read resolves through a getter and the Rust compiler specialises the
function per shape — concrete and fast, with no runtime field lookup.

The forms listed above multiply the emission cases (multiple witness bounds,
return-position generics, chained bounds for nested rows) and are planned later
increments of the same design. Until each lands, the compiler stops here rather
than emit Rust that would fail to build after `ipe build` already reported
success.
