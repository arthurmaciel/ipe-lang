# IPE-L0103: function-valued parameters/returns not supported yet

Your annotation describes a value that takes a function as an argument
or hands one back as a result — a function type sitting in argument or
return position. Sky can read the signature, but this version can't
lower values that pass functions around yet.

This is a feature Sky hasn't grown into, not a flaw in your design.
For now, the parameters and result of a value annotation need to be
ordinary data types (`Int`, `String`, a union you defined), not
functions.

`[feature: higher-order-values]`

A parameter that is itself a function trips this:

```sky
applyTwice : (Int -> Int) -> Int -> Int
applyTwice f x =
    f (f x)
```

So does returning a function:

```sky
adder : Int -> (Int -> Int)
adder n =
    \x -> x + n
```

Until higher-order values land, inline the work directly instead of
threading a function through:

```sky
bumpTwice : Int -> Int
bumpTwice x =
    x + 1 + 1
```

This is a current limitation, not a mistake you made. If higher-order
functions matter for what you're building, please nudge us at
https://codeberg.org/sky-lang/sky-rust/issues.
