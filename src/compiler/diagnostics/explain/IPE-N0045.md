# IPE-N0045: main selects its shape at runtime, but a shape is a compile-time choice

Every Ipê program declares what it *is* through its `main`. A `main = Web.app …` is a web app; a `main = Tui.app …` is a full-screen terminal app; a plain `main : Task Error ()` is a script. This kind — the program's *shape* — is fixed when the code is compiled, read straight off the head of `main`. It is not a value the program picks while it runs.

So `main` cannot branch between shapes. This is refused:

```ipe ipe:skip
module Main exposing (main)

import Ipe.Tea.Web as Web
import Ipe.Tea.Tui as Tui

main =
    if runningInBrowser then
        Web.app webConfig
    else
        Tui.app tuiConfig
```

At the moment the head of `main` is an `if` (or a `case`) whose branches are different app entries, "which kind of program is this?" would only be answerable at run time — and the whole toolchain (which runtime to link, which entry point to emit, which effects are even in scope) needs the answer before the program runs. A shape decided from a value has no single answer, so the compiler turns it back rather than guessing.

The fix is to commit `main` to one shape, and move the run-time choice *inside* that shape:

```ipe ipe:skip
module Main exposing (main)

import Ipe.Tea.Web as Web

main =
    Web.app webConfig
```

Anything you wanted to decide at run time still can be — but it belongs in that shape's own logic (its `init`, `update`, or the `Task` a script runs), where the program is already running and a value is exactly the right way to choose. What cannot vary is the shape itself.

If the program is a plain script, make `main` a `Task Error ()`: a task is free to branch on any value it likes, because a script is one shape no matter what the task computes.

```ipe ipe:skip
module Main exposing (main)

import Ipe.Task as Task

main =
    if shouldGreet then
        Task.succeed ()
    else
        Task.succeed ()
```

The rule in one line: one `main`, one shape, chosen when you write it — never when it runs.
