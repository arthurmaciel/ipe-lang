# IPE-L0105: parameter destructuring not supported yet

One of your function parameters is a pattern that pulls a value apart —
something like `(Just x)` or a constructor with fields — rather than a
plain name. Ipe can parse it, but this version requires every function
parameter to be a simple variable; destructuring in the parameter list
isn't compiled yet.

This is a feature Ipe hasn't reached, not a mistake in your function.
The fix for now is to take the whole value as a named parameter and
take it apart in the body with `case`.

`[feature: param-patterns]`

Destructuring directly in the parameter list trips this:

```ipe ipe:error
unwrap : Maybe Int -> Int
unwrap (Just x) =
    x
```

Bind the argument to a plain name instead, then match inside:

```ipe
unwrap : Maybe Int -> Int
unwrap value =
    case value of
        Just x -> x
        Nothing -> 0
```

Plain-name parameters are always fine:

```ipe
double : Int -> Int
double n =
    n + n
```

This is a current limitation, not an error you introduced. If parameter
patterns would help your code read better, please nudge us at
https://github.com/arthurmaciel/ipe-lang/issues.
