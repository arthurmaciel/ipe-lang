# IPE-I0100: ICE: match on unknown variant

Sorry — the compiler got confused about one of your `case` branches. While
lowering a match, it found a branch matching on a constructor that it didn't
recognise as belonging to the type being matched. By this stage every
constructor should already have been checked and resolved, so seeing an
unknown one means an internal invariant slipped.

This is a bug in the Ipe Rust compiler, not a mistake in your code. If your
`case` matches on real constructors of a type you defined, it should compile
— if it reaches here instead, the fault is on our side.

A straightforward match over a small type:

```ipe
module Main exposing (main)

import Ipe.Io as Io

type Light
    = Red
    | Green

describe : Light -> String
describe light =
    case light of
        Red -> "stop"
        Green -> "go"

main : Task ()
main =
    Io.println (describe Red)
```

A three-constructor type, all branches present:

```ipe
module Main exposing (main)

type Signal
    = Lo
    | Mid
    | Hi

rank : Signal -> Int
rank signal =
    case signal of
        Lo -> 0
        Mid -> 1
        Hi -> 2
```

This is correct Ipe — every branch names a real variant — and should just
compile:

```ipe
module Main exposing (main)

type Answer
    = Yes
    | No

toText : Answer -> String
toText answer =
    case answer of
        Yes -> "yes"
        No -> "no"
```

This is a bug in the Ipe Rust compiler — not your fault. Please report it
(with this source + `ipec --version`) at

https://github.com/arthurmaciel/ipe-lang/issues

so we can find the lowering gap.
