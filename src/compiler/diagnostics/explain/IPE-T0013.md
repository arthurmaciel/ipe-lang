# IPE-T0013: constructor pattern binds the wrong number of fields

A constructor pattern in a `case` listed a number of payload sub-patterns
that does not match the constructor's declaration. Every constructor has a
fixed field count — the number of types written after its name in the
`type` declaration — and a pattern must bind exactly that many.

## Too few

`Node` is declared with three fields, so a pattern that names only two
cannot describe a `Node`:

```ipe ipe:error
type Tree = Leaf | Node Tree Int Tree

sumTree : Tree -> Int
sumTree t =
    case t of
        Leaf -> 0
        Node l r -> sumTree l + sumTree r   -- missing the Int field
```

Bind all three fields (use `_` for the ones you ignore):

```ipe
type Tree = Leaf | Node Tree Int Tree

sumTree : Tree -> Int
sumTree t =
    case t of
        Leaf -> 0
        Node l n r -> sumTree l + n + sumTree r
```

## Too many

A nullary constructor binds nothing, so giving it a payload variable is an
error:

```ipe ipe:error
type Color = Red | Green

name : Color -> Int
name c =
    case c of
        Red x -> x        -- Red has no fields
        Green -> 0
```

Drop the extra sub-pattern: `Red -> …`. The number of sub-patterns must
equal the number of fields the constructor declares.
