# IPE-P0016: float literal out of range

I read a float literal whose magnitude is larger than the biggest
fractional number Ipe can hold. Every character is a valid digit, but
the value they spell overflows to infinity, so I can't store the
number you actually wrote — and I stop here rather than pretend a
finite literal became infinity.

## Explanation

Ipe's `Float` is a 64-bit IEEE 754 floating-point number. It can hold
values up to roughly `1.8e308`; anything past that has no finite
representation and rounds to positive or negative infinity. A literal
like `1e400` therefore cannot become the number on the page — turning
it into `inf` silently would hand the rest of the program a value the
source never named. To keep what you wrote and what runs in step, I
reject the literal at this point instead of accepting the overflow.

This is the floating-point twin of the integer case: an `Int` literal
too big for 64 bits is rejected the same way (IPE-P0013). A finite
literal — including a plain `0.0`, a tiny `1e-300`, or a large but
in-range `1e308` — passes through untouched.

## Examples

A literal past the `Float` ceiling lands here:

```ipe ipe:error
huge : Float
huge =
    1e400
```

If the magnitude is genuinely needed but the value is in range, a
finite exponent works:

```ipe
big : Float
big =
    1e308
```

If the quantity must grow without an upper bound, model it with a type
built for arbitrary-precision magnitudes rather than a bare `Float`
literal:

```ipe
balance : Float
balance =
    1.5
```

## Comparison

It is like a measuring jug marked up to one litre. You can read off any
amount it can actually hold, but asking it to show "a thousand litres"
is meaningless — the jug has no mark that high, so the honest answer is
to say so rather than let it overflow and report a wrong reading.

## Names and origins

A **float** is short for *floating-point number*: the decimal point
"floats" to wherever the exponent puts it, so one format spans both
tiny and huge values. *Overflow* is the old engineering word for a
container filled past its capacity — here the value exceeds the largest
magnitude the 64-bit format can represent, so it spills over into
*infinity*, from Latin *infinitas*, "without end".
