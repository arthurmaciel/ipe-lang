# IPE-N0048: two definitions fold to one generated Rust name

Ipê compiles to Rust, and each of your definitions gets a generated Rust name. That name is built by mangling the definition's module path and its own name into a single identifier. The mangling folds away some distinctions — it lower-cases, it flattens the module boundary into the name — so two definitions that look different in Ipê can end up with the *same* Rust name.

When that happens I stop, because emitting two Rust items under one identifier is a broken crate (the Rust compiler would reject it). This is not a genuine redefinition — your two definitions really are different — so I do not guess which one to keep. I name both, show the shared Rust name, and ask you to rename one.

The two classic ways this happens:

A camel-case name and a snake-case name that fold together. These are two different field names in Ipê, but both mangle to the same witness trait:

```ipe ipe:error
type alias Person a =
    { a | firstName : String, first_name : String }
```

A module boundary that disappears in the fold. Two values whose module path and name flatten together — one nested a level deeper — mangle to the same Rust name:

```ipe ipe:error
borderRounded : Style
borderRounded =
    -- folds to the same Rust name as `Border.rounded` below
    rounded
```

To fix this, rename one of the two colliding definitions so they no longer share a generated name — for example, give one of the fields a distinct name:

```ipe
type alias Person a =
    { a | firstName : String, familyName : String }
```
