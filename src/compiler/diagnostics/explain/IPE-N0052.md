# IPE-N0052: a wasm build carries a Cmd, Sub or Task inside a Decoder

A `Decoder` can be shared across threads on every target, so the value it
produces must be shareable too. In a wasm build (a browser client or
a WASI module) the effect carriers — `Cmd`, `Sub` and `Task` — are
single-threaded and cannot be shared. A decoder whose element is, or holds, one
of them has no valid build, so `ipe` refuses it.

The element is refused whether the carrier appears directly (`Decoder (Cmd
Msg)`), inside another type (`Decoder (List (Task Error Int))`, a custom type
with a `Cmd` field), or through a type variable a generic definition places in
a decoder element without its signature exposing that decoder.

## Example

```ipe ipe:skip
-- Rejected (IPE-N0052) in a wasm build: the decoder produces a Cmd.
saveOnLoad : Decoder (Cmd Msg)
saveOnLoad =
    Decode.map (\name -> Task.attempt Saved (store name)) (Decode.field "name" Decode.string)
```

## Fix

Decode plain data into a message, and build the `Cmd`, `Sub` or `Task` from
that message in `update`:

```ipe ipe:skip
nameDecoder : Decoder Msg
nameDecoder =
    Decode.map GotName (Decode.field "name" Decode.string)

update : Msg -> Model -> ( Model, Cmd Msg )
update msg model =
    case msg of
        GotName name ->
            ( model, Task.attempt Saved (store name) )

        Saved _ ->
            ( model, Cmd.none )
```

A generic helper that decodes into its own type variable should expose the
decoder in its signature (`decodeWith : Decoder a -> Decoder (List a)`), so
each use is checked at its concrete type.
