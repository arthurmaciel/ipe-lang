# IPE-T0018: wildcard arm swallows constructors a finite type could name

Your `case` expression uses a wildcard `_` (or a variable binder like `other`)
as a catch-all, but the compiler knows the complete set of constructors your
type has — so the wildcard is covering a finite, nameable list of variants.

The code examples below are illustrative Ipê source snippets, not shell commands.

This is a warning, not an error: the code is correct and will compile. The
concern is what happens next time someone adds a new variant to the type. With
an explicit list of constructors, the compiler will flag every `case` that
needs updating. With a wildcard, the new variant falls through silently,
inheriting whatever the `_` arm does — which is almost certainly wrong.

Here `Shape` has three constructors, two are listed, and `_` silently covers
`Triangle`:

```ipe
type Shape
    = Circle
    | Square
    | Triangle

describe : Shape -> String
describe shape =
    case shape of
        Circle ->
            "a round shape"

        Square ->
            "a four-sided shape"

        _ ->
            "some other shape"
```

Replace the wildcard with the remaining constructors so every future addition
is caught at this site:

```ipe
type Shape
    = Circle
    | Square
    | Triangle

describe : Shape -> String
describe shape =
    case shape of
        Circle ->
            "a round shape"

        Square ->
            "a four-sided shape"

        Triangle ->
            "a three-sided shape"
```

If you genuinely want a default arm because the type has many constructors and
most should behave the same way, list the ones that need special handling and
give each its own arm, then use `_` only for what is truly a default:

```ipe
type Status
    = Loading
    | Ready
    | Error
    | Timeout
    | Cancelled

label : Status -> String
label status =
    case status of
        Loading ->
            "loading…"

        Ready ->
            "ready"

        _ ->
            "unavailable"
```
