# IPE-T0010: this case does not handle every possibility

Your `case` expression looks at a value that could be one of several
constructors, but it doesn't have a branch for every one of them. If
the value ever turned out to be one of the missing kinds at run time,
there'd be no branch to take — so I require every possibility to be
covered, and I list the ones you've left out.

Ipe has no catch-all `_` pattern, so you handle each constructor
explicitly. That's deliberate: when you later add a new constructor to
a type, every `case` over it that needs updating will point you right
at the gap, instead of silently falling through.

Here a `case` over a colour forgets one of its constructors:

```ipe ipe:error
type Colour
    = Red
    | Green
    | Blue

name : Colour -> String
name colour =
    case colour of
        Red ->
            "red"

        Green ->
            "green"
```

`Blue` is missing. Add a branch for it so every case is handled:

```ipe
type Colour
    = Red
    | Green
    | Blue

name : Colour -> String
name colour =
    case colour of
        Red ->
            "red"

        Green ->
            "green"

        Blue ->
            "blue"
```

The same applies to any union — once you cover every constructor, the
`case` is complete:

```ipe
type Toggle
    = On
    | Off

label : Toggle -> String
label toggle =
    case toggle of
        On ->
            "on"

        Off ->
            "off"
```

The check also looks *inside* nested patterns. Here the `Just` arm only
matches when the inner value is itself a `Just`, so `Just Nothing` is
left out — and the report names that exact missing pattern:

```ipe ipe:error
flatten : Maybe (Maybe Int) -> Int
flatten m =
    case m of
        Just (Just a) ->
            a

        Nothing ->
            0
```

Cover the gap by handling the inner value completely — for example, by
matching the outer constructor once and branching on the inner:

```ipe
flatten : Maybe (Maybe Int) -> Int
flatten m =
    case m of
        Just inner ->
            case inner of
                Just a ->
                    a

                Nothing ->
                    0

        Nothing ->
            0
```
