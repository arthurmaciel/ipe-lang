# IPE-L0127: a value holding a function is used more than once

A binding whose type embeds a function — a bare function value, or one held
inside a `Maybe` / `Result` / user-union constructor payload (#90) — was used
more than once in a value-CONSUMING (non-call) position.

The Rust backend lowers a Ipe function value to `Box<dyn Fn(..) -> R + Send +
'static>`. That type does not implement `Clone`, so it can be moved exactly
once. **Calling** the value is unlimited — `Fn::call` takes `&self`, so it
only borrows — but a second use that is not a direct call (storing it again,
passing it to another function, returning it a second time) would move an
already-moved value, which `cargo` rejects as E0382.

```ipe
-- before (IPE-L0127 — `mf` is forwarded twice)
consumeTwice mf =
    ( callSecond mf, callSecond mf )
```

## How to fix

**Call the function at each use site** instead of forwarding the wrapping
value more than once — calling is unlimited:

```ipe
-- after (both calls happen through ONE extraction — accepted)
callTwice mf =
    case mf of
        Just f ->
            f 1 + f 2

        Nothing ->
            0
```

**Re-construct the value at each use** when the underlying function is cheap
to rebuild (e.g. a top-level named function referenced bare):

```ipe
inc n =
    n + 1

-- after (two independent constructions, each used once)
useTwice =
    ( consume (Just inc), consume (Just inc) )
```

**Restructure the code to a single linear use** — thread the value through
one call chain rather than branching it into two independent consumers.

## Why this happens

`Box<dyn Fn(..) -> R + Send + 'static>` is the only sound Rust representation
for a first-class Ipe function value (it may capture arbitrary state), and
`Box<dyn Fn>` is not `Clone`. This is a narrow, conservative gate — it will be
superseded once a general last-use analysis (an extension of the existing
non-Clone-capture machinery, IPE-L0126) can tell a genuinely last use from an
earlier one and rewrite accordingly, the way `String`/other `Clone` bindings
already are today.

## Types affected

- Function types (`a -> b`), bare or curried
- `Maybe (a -> b)` / `Result e (a -> b)` — a function-carrying constructor
  payload (#90)
- A user union whose constructor holds a function-typed field
