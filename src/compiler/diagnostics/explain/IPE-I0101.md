# IPE-I0101: ICE: duplicate match arm

Sorry about this — the compiler found the same constructor handled twice in
one `case`, but only after it had already built the match's internal form.
Duplicate branches should have been caught and reported to you with a clear,
user-facing message long before this point, so reaching here means an
earlier check didn't fire when it should have.

This is a bug in the Ipe Rust compiler, not a mistake in your code. A `case`
that lists each constructor exactly once should compile cleanly; if a genuine
duplicate slips through to this stage, that's our oversight to fix.

A well-formed match handles each constructor once:

```ipe
module Main exposing (main)

type Light
    = Red
    | Green

describe : Light -> String
describe light =
    case light of
        Red -> "stop"
        Green -> "go"
```

Adding more constructors, still one branch each:

```ipe
module Main exposing (main)

type Suit
    = Hearts
    | Spades
    | Clubs

colour : Suit -> String
colour suit =
    case suit of
        Hearts -> "red"
        Spades -> "black"
        Clubs -> "black"
```

This is correct and should compile — no constructor is repeated:

```ipe
module Main exposing (main)

type Answer
    = Yes
    | No

toText : Answer -> String
toText answer =
    case answer of
        Yes -> "yes"
        No -> "no"
```

This is a bug in the Ipe Rust compiler — not your fault. Please report it
(with this source + `ipe version`) at

https://github.com/arthurmaciel/ipe-lang/issues

and we'll restore the earlier duplicate check.
