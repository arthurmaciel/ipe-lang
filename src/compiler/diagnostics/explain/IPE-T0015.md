# IPE-T0015: parameter pattern must be irrefutable

A **parameter** is a *binding* position, not a *discrimination* position: it
must match **every** value of its type. A pattern that can *fail* to match some
value of its type is **refutable** — it is fine as a `case` arm (which offers
other arms to fall through to) but not as a lambda parameter, a function-def
head, or a `let` binder, where there is nowhere to fall through to.

Rejecting a refutable parameter *here*, before code generation, means a
well-typed program can never fail a pattern match at runtime — there is no
hidden `panic!` on a function argument and no 5xx / denial-of-service surface if
that argument comes from untrusted input.

## Irrefutable (allowed) vs refutable (rejected)

| Pattern | Kind | As a parameter |
|---|---|---|
| `x`, `_` | binds / ignores every value | allowed |
| `(a, b)` | one product constructor, sub-patterns irrefutable | allowed |
| `{ name, age }` | record field-pun (one constructor) | allowed |
| `p as name` | irrefutable when `p` is | allowed |
| `Just x`, `Ok v` | one of several constructors | **refutable → error** |
| `1`, `'a'`, `"hi"`, `True` | a single literal value | **refutable → error** |
| `[a]`, `[]`, `x :: xs` | a specific list shape | **refutable → error** |

## Example

```ipe ipe:error
-- error: `Just x` can fail to match `Nothing`
greet : Maybe String -> String
greet (Just name) = "Hi " ++ name
```

Bind the whole value and discriminate with `case`, which forces you to handle
every shape:

```ipe
greet : Maybe String -> String
greet m =
    case m of
        Just name -> "Hi " ++ name
        Nothing   -> "Hi there"
```

Tuple and record parameters stay ergonomic because they *are* irrefutable:

```ipe
-- fine: one product constructor, both fields bound
fullName : { first : String, last : String } -> String
fullName { first, last } = first ++ " " ++ last

dist : ( Int, Int ) -> Int
dist ( x, y ) = abs x + abs y

ignore : a -> Int
ignore _ = 0
```

## Note (divergence from Elm)

Even a single-constructor union parameter (`\(Wrapper x) -> …`) is reported
here. The rule is deliberately syntactic — it needs no type lookup, so the
front-end gate and the code generator agree exactly on which parameters are
legal. Wrap-and-`case`, or bind the whole value, as above.
