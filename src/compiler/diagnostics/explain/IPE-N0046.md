# IPE-N0046: Web.app init annotation uses a type variable where WebReq is required

`Web.app`'s `init` function always receives a `WebReq` — the per-request
context carrying `path`, `query`, `method`, `params`, `headers`, and `cookies`.
The request type is not user-choosable: it is fixed by the runtime's HTTP layer.

When you annotate `init` with a free type variable (`a`, `req`, etc.) the
compiler still accepts the program (the variable unifies with `WebReq` at the
call site), but the emitted Rust function becomes generic (`fn init<T1: Clone>`).
A generic init:

- Cannot read `req.path`, `req.cookies`, etc. — the type variable has no
  known fields, so field access is rejected at the point where it would be
  most useful.
- Violates the make-invalid-states-unrepresentable principle: the annotation
  claims the function works for *any* request shape, which is a lie.
- Produces a misleading public signature that hides the real contract.

## Fix

Write the concrete annotation, or omit the annotation entirely:

```ipe
-- Explicit and correct:
init : WebReq -> ( Model, Cmd Msg )
init req = ( { path = req.path }, Cmd.none )

-- Also fine — inference pins the arg to WebReq:
init req = ( { path = req.path }, Cmd.none )
```

Do not write:

```ipe
-- Rejected (IPE-N0046):
init : a -> ( Model, Cmd Msg )
init _req = ( defaultModel, Cmd.none )
```

If you do not need the request in `init`, annotate with `WebReq` and ignore
the argument with `_`:

```ipe
init : WebReq -> ( Model, Cmd Msg )
init _ = ( defaultModel, Cmd.none )
```

## Background

`WebReq` is an opaque nullary type at the type level (no bare record literal
can masquerade as the runtime struct — the same posture as the opaque server
`Request`), but its fixed field set is readable via the deferred field-access
pass. Reads lower to `(req).<field>.clone()` against `ipe_runtime::web::WebReq`
directly.
