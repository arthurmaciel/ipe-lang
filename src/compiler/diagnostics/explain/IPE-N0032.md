# IPE-N0032: type alias expansion too deep or too large

A `type alias` chain or diamond caused the compiler to exceed its expansion budget before it could produce a fully-expanded type. Two independent limits protect against two different pathological shapes:

- **Depth limit (256):** a long straight chain of aliases (`type alias A1 = A0`, `type alias A2 = A1`, …, `type alias A300 = A299`) stacks one native frame per expansion and can overflow the thread stack. The depth cap mirrors the parser's own nesting limit.
- **Node limit (100 000):** a diamond of aliases where each level doubles the work (`type alias A1 = (A0, A0)`, `type alias A2 = (A1, A1)`, …) is acyclic so the cycle guard never fires, but the total number of nodes produced grows exponentially. The node budget bounds that regardless of tree shape.

When the compiler hits either limit it rejects the program here rather than crashing or hanging.

A well-typed program never needs alias chains this deep or this wide. If you are hitting this limit legitimately, the fix is to break the chain into smaller named types:

```sky
-- error: a 300-deep alias chain trips the depth limit
type alias Chain300 = Chain299
-- (and so on...)

-- fixed: introduce a concrete named type at an intermediate point
type alias SmallChain = Int
type alias LargerChain = (SmallChain, SmallChain)
```

Diamond aliases that fan out exponentially are the more common source of IPE-N0032. Thirty levels of doubling already exceeds a billion nodes:

```sky
-- error: 30 levels of (Prev, Prev) produces > 1 billion expansion nodes
type alias A1 = (Int, Int)
type alias A2 = (A1, A1)
-- ...
type alias A30 = (A29, A29)

-- fixed: name the shared structure rather than duplicating it
type alias Pair = (Int, Int)
type alias Quad = (Pair, Pair)
```

A direct self-referential alias is also rejected, but with a different error (the alias is cyclic and the path-based cycle guard fires first):

```sky
-- this is a different error (cycle), not IPE-N0032
type alias Loop = Loop
```
