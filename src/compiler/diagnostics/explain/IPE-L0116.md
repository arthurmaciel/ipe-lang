# IPE-L0116: refutable pattern-discrimination shape not supported yet

A `case` discriminated values with a refutable pattern shape the compiler
cannot yet lower to a Rust `match`. The shapes that trip this are
discrimination through **cons / list patterns** and **guarded arms** — the
pattern forms whose lowering carrier is not in place yet.

The exhaustiveness checker runs first, so a *non-exhaustive* `case` is reported
as `IPE-T0010` with the missing pattern. A `case` that is exhaustive but uses
an unsupported discrimination shape is gated here cleanly rather than
mis-lowered.

## Discrimination that DOES work

Several arms may head-match the **same constructor** and differ only in a
nested sub-pattern. Each arm lowers to its own Rust `match` arm, in source
order, so this is fully supported:

```ipe
type Opt a = Som a | Non

flatten : Opt (Opt Int) -> Int
flatten oo =
    case oo of
        Som (Som x) -> x        -- arm 1 for `Som`
        Som Non     -> 0        -- arm 2 for `Som`
        Non         -> 1
```

A nested constructor pattern with a single arm per constructor also works:

```ipe
type Tree = Node Tree Int Tree | Leaf

label : Tree -> Int
label t =
    case t of
        Node _ x _ -> x
        Leaf -> 0
```

An irrefutable nested payload (a tuple or record) works in one arm:

```ipe
type Pair = Pair (Int, Int)

addPair : Pair -> Int
addPair p =
    case p of
        Pair (a, b) -> a + b
```

`[feature: nested-ctor-discrimination]`

This is a current limitation of the Ipe Rust compiler, not a problem with
your code. If a discrimination shape you need is gated here, please tell us at
https://codeberg.org/ipe-lang/issues.
