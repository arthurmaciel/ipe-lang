# IPE-L0114: function value in a constructor payload not supported yet

A data constructor was given a function value as one of its payload fields,
in one of the two shapes that remain unsound to lower today: a **collection**
of functions (`List` / `Dict` / `Set`) or a **curried (two-or-more-argument)
payload flowing into `Maybe.andMap` / `Result.andMap`**.

Storing a function in `Ok` / `Just` (or a user union's constructor) is
**supported** — `Ok f` / `Just f` construct the runtime's `IpeResult` /
`IpeMaybe` enums, whose derives are generic-bounded, and a user union's
derives are automatically dropped when a payload embeds a function. What is
left gated is narrower:

## Collections of functions — still gated

`List (a -> b)`, `Dict k (a -> b)`, and `Set (a -> b)` are not yet supported:
several collection kernels (`DictGet`, `ListMap`, …) blanket-`.clone()` their
element, and a `Box<dyn Fn>` element is not `Clone`.

```ipe ipe:skip
handlers =
    [ (\n -> n + 1), (\n -> n * 2) ]   -- List (Int -> Int): not yet

main = println "unreachable"
```

## Curried `andMap` payload — still gated

`Maybe`/`Result`'s higher-order kernels (`map`, `map2`..`map5`, `mapError`,
`andMap`) apply their callback to an EXACT number of arguments. A callback
with residual arity (a curried `andMap` payload, a three-argument function
handed to `map2`, …) leaves a leftover function after the applications the
kernel performs — there is no sound lowering for that shape yet (a full
curried-applicative chain is tracked separately). This is primarily a type
error (`IPE-T0001` when the callback pins directly, or `IPE-T0014` through a
generic forwarder — see that page's higher-order-kernel section) raised
before lowering ever runs; this lowering-time check is a defense-in-depth
backstop behind the `andMap` members of that family, so any of those codes
may be the one you see:

```ipe ipe:error
add3 a b c =
    a + b + c

main =
    Just add3
        |> Maybe.andMap (Just 1)   -- payload is `Int -> Int -> Int`: not yet
        |> Maybe.withDefault 0
```

An exact-arity callback works (`map` with a one-argument function, `map2`
with a two-argument function, a single-argument payload through `andMap`),
and so does storing any other function value in `Ok` / `Just` / a user
union's payload:

```ipe ipe:skip
inc n =
    n + 1

main =
    Just inc
        |> Maybe.andMap (Just 41)
        |> Maybe.withDefault 0
        |> String.fromInt
        |> println   -- 42
```

A declared function-typed payload also works today, including through an
extracted-and-called-twice payload:

```ipe ipe:skip
type Retryish e
    = RetryAlways
    | RetryWhen (e -> Bool)

alwaysTrue : Retryish Int
alwaysTrue =
    RetryWhen (\_ -> True)

main =
    case alwaysTrue of
        RetryWhen f ->
            println (if f 1 && f 2 then "retry" else "stop")

        RetryAlways ->
            println "retry"
```

`[feature: ctor-payload-function]`

This is a current limitation of the Ipe Rust compiler, not a problem with
your code. If a function-carrying collection or a curried `andMap` chain
matters to your project, please tell us at
https://github.com/arthurmaciel/ipe-lang/issues.
