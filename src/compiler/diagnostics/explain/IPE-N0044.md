# IPE-N0044: the CustomElement.fromFile constructor is malformed at its use site

Ipê talks to a JavaScript widget through one typed door: the reserved `CustomElement down up` type. You name the widget's hook file with the reserved `CustomElement.fromFile` constructor, and you use the resulting handle in a view with `CustomElement.node`.

The `CustomElement.fromFile` constructor is deliberately narrow. It is legal in exactly ONE place — as the whole body of a binding you have annotated `CustomElement down up` — and it takes exactly ONE thing: a single string literal naming the widget-hook JavaScript file inside your project. That is the same discipline the standard library's `Kernel.kernel "…"` aliases use: the compiler must be able to read the file path at build time, so it must be spelled out as a literal.

This is the one accepted shape:

```ipe ipe:skip
module Main exposing (main)

import Ipe.Ffi.Js.CustomElement as CustomElement

codeEditor : CustomElement EditorState EditorEvent
codeEditor =
    CustomElement.fromFile "js/code-editor.js"

view model =
    CustomElement.node codeEditor (stateOf model) EditorChanged
```

The string is not a type parameter — the two parameters `down` and `up` are the *seal*, the shapes that cross the Ipê↔JS boundary. The JavaScript file is a plain value argument. And because the compiler resolves that path at build time, it must point at a file that actually exists, inside your project — a `..` that climbs out of the project root is refused (a build reading an arbitrary file outside the project is a path-traversal footgun, so the safe outcome is the only one allowed).

Each of these trips the gate — a non-literal argument (the path cannot be read at build time), and a `..` escape:

```ipe ipe:skip
module Main exposing (main)

whichFile : String
whichFile =
    "js/editor.js"

codeEditor : CustomElement EditorState EditorEvent
codeEditor =
    CustomElement.fromFile whichFile
```

```ipe ipe:skip
module Main exposing (main)

codeEditor : CustomElement EditorState EditorEvent
codeEditor =
    CustomElement.fromFile "../secrets/editor.js"
```

To fix it, give the binding a `CustomElement down up` annotation, make its whole body `CustomElement.fromFile "<js-path>"` with a single string literal, keep the path inside your project (no `..`), and make sure the file is really there.
