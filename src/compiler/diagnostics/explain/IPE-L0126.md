# IPE-L0126: non-Clone capture in a closure is not yet supported

A closure captured a binding whose type does not implement `Clone` — such as a
`Task`, `Fn`/function value, `Decoder`, `Cmd`, or `Sub` — and used it in a
position other than a direct function call.

The Rust backend lowers Ipe closures to `Box<dyn Fn(…) -> …>`, which requires
captured bindings to be cloneable (so the closure can be called multiple times).
Closures that *call* a captured function are fine today — `Fn::call` only
borrows the capture. But forwarding a function-typed value out of a closure
(storing it in a record, returning it, passing it to another HOF) consumes the
capture, making the closure `FnOnce` when a `Fn` slot is required.

## How to fix

**Call the function inside the closure** instead of forwarding the value:

```ipe ipe:error
-- before (forwarding — IPE-L0126)
let wrapped = \x -> applyTwice f x  -- f is a function; forwarded, not called

-- after (call at the use site)
let wrapped = \x -> f (f x)
```

**Bind the result outside the closure** when possible:

```ipe ipe:error
-- before
let result = someTask |> Task.andThen (\_ -> otherTask)

-- if otherTask can be evaluated once and reused, bind it first:
let theResult = Task.run otherTask
let result = someTask |> Task.andThen (\_ -> Task.succeed theResult)
```

**Wrap the forwarding in a named top-level function** when the closure must
pass the function along:

```ipe ipe:error
-- before (closure forwarding a decoder)
let mapped = \d -> JsonDec.map transform d

-- after (top-level named function)
mappedDecoder d =
    JsonDec.map transform d
```

## Why this happens

Ipe closures lower to `Box<dyn Fn(…) -> …>` in Rust. Captured values that are
not `Clone` can only be consumed once, producing `FnOnce`; but the `Fn` trait
is required for closures that may be called more than once. This restriction will
be relaxed in a future release once first-class function values gain a richer
representation.

## Types affected

- `Task a` / `Cmd a` / `Sub a`
- Function types (`a -> b`)
- `Decoder a`
- Server request / response / route types
