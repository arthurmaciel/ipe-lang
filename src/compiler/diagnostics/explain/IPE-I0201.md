# IPE-I0201: ICE: dangling value/variant symbol

Sorry about this — during code generation the backend was handed a value,
variant, or parameter symbol that resolved to nothing (an empty or dangling
name). It expected a real identifier there and couldn't proceed without one.

This is a bug in the Ipe Rust compiler, not a mistake in your code. Every
binding, constructor, and parameter you write should carry a proper name all
the way through to the backend; an empty one slipping in means an internal
step dropped or mis-recorded it.

A program with named values and parameters throughout:

```ipe
module Main exposing (main)

import Ipe.Io as Io

greet : String -> String
greet who = who

main : Task ()
main =
    Io.println (greet "Ipe")
```

A type whose variants each carry a name:

```ipe
module Main exposing (main)

type Answer
    = Yes
    | No

toText : Answer -> String
toText answer =
    case answer of
        Yes -> "yes"
        No -> "no"
```

This is well-formed Ipe — every name is present — and should compile:

```ipe
module Main exposing (main)

import Ipe.Io as Io
import Ipe.String as String

add : Int -> Int -> Int
add x y = x + y

main : Task ()
main =
    Io.println (String.fromInt (add 1 2))
```

This is a bug in the Ipe Rust compiler — not your fault. Please report it
(with this source + `ipe version`) at

https://github.com/arthurmaciel/ipe-lang/issues

and we'll find where the name went missing.
