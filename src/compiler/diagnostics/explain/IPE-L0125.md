# IPE-L0125: app Msg is not admissible for this app shape

The message type (the **Msg**) dispatched through an app entry point's
`update` must satisfy the runtime bound that app shape requires. Your Msg
does not, so `ipec` rejects it here instead of letting the generated Rust
fail to compile.

* **`Ipe.Web`** requires `Msg: Clone + Send + Sync + Debug + 'static`
  (messages are sent across threads and logged).
* **`Ipe.Tui`** and **`Ipe.Webview`** require `Msg: Clone + Send + 'static`.

Both bounds are covered by `ipec`'s derivable predicate: a Msg made of plain
data (ints, floats, strings, bools, bytes, lists, tuples, records, and your
own enums of plain data) always satisfies them. The values that are **not**
admissible in a Msg are effects and handles — `Cmd`, `Sub`, `Task`,
`Decoder`, `Db`, server/live request handles, and functions.

Note: `Html` / `Element` / `Color` **are** admissible in a Msg (they derive
`Clone + Debug + PartialEq`). Unlike the Model gate for `Ipe.Web`, Msg is
**not** required to be serialisable — messages are transient and are never
persisted to the session store.

This trips the gate — a Msg variant carries a function:

```ipe
type Msg
    = Noop
    | SetHandler (Int -> String)    -- functions are not Clone
```

A Msg variant carrying a `Cmd` trips it too:

```ipe
type Msg
    = Noop
    | WithEffect (Cmd Msg)          -- Cmd is not Clone
```

Keep only plain data in Msg variants. Store callbacks as data (e.g. an
index, a string key, or an ADT tag) and look up the function in `update`:

```ipe
type Msg
    = Noop
    | ButtonClicked Int
    | LabelChanged String
```
