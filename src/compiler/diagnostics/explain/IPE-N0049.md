# IPE-N0049: a pattern binds the same name twice

A single pattern introduces the same variable name more than once. Each name a
pattern binds becomes a distinct value in the branch that follows, so binding
one name twice is ambiguous — a later use of that name could mean either
occurrence, and the two are not required to be equal. Rather than silently keep
one binding and shadow the other, the compiler rejects the pattern.

```ipe ipe:error
module Pair exposing (dup)

dup : ( Int, Int ) -> Int
dup pair =
    case pair of
        ( x, x ) ->
            x
```

The pattern `( x, x )` binds `x` twice. If the intent was to require the two
components to be equal, that is a comparison, not a binding — a pattern cannot
express it.

## To fix

Give each position its own name, then compare or combine them in the body:

```ipe
module Pair exposing (equalParts)

equalParts : ( Int, Int ) -> Bool
equalParts pair =
    case pair of
        ( left, right ) ->
            left == right
```

If one component is genuinely irrelevant, bind it with the wildcard `_`, which
may appear any number of times:

```ipe
module Pair exposing (first)

first : ( Int, Int ) -> Int
first pair =
    case pair of
        ( x, _ ) ->
            x
```
