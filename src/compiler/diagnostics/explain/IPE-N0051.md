# IPE-N0051: terminal input is a subscription, not an app config field

A `Tui.tea` or `Cli.tea` config passes terminal input as a record field —
`onKey` for a full-screen app, `onLine` for a line app. Neither entry has such a
field. Both take exactly the four pieces every TEA app has: `init`, `update`,
`view`, and `subscriptions`. Input is an event like a timer tick, so it arrives
through `subscriptions`.

```ipe ipe:error
-- rejected: `onLine` is not a `Cli.tea` config field
main =
    Cli.tea
        { init = init
        , update = update
        , view = view
        , subscriptions = subscriptions
        , onLine = GotLine
        }
```

## How to fix

Remove the field and subscribe to the input from `subscriptions`, through your
app's own `Sub` module. A line app subscribes with `Cli.Sub.onLine`:

```ipe ipe:skip
import Ipe.Tea.Cli as Cli
import Ipe.Tea.Cli.Sub as Sub

subscriptions : Model -> Sub Msg
subscriptions _model =
    Sub.onLine GotLine

main =
    Cli.tea
        { init = init
        , update = update
        , view = view
        , subscriptions = subscriptions
        }
```

A full-screen app subscribes to keys with `Tui.Sub.onKey`. Its handler takes a
`{ kind : String, value : String }` key event:

```ipe ipe:skip
import Ipe.Tea.Tui as Tui
import Ipe.Tea.Tui.Sub as Sub

subscriptions : Model -> Sub Msg
subscriptions _model =
    Sub.onKey KeyPressed
```

Because input is now an ordinary subscription, it combines with the others.
`Sub.batch [ Sub.onKey KeyPressed, Sub.every 1000 Tick ]` listens for keys and
ticks at once, and a `subscriptions` that returns `Sub.none` for some model
simply stops listening for input in that state.

## Why this is an error

A field the entry does not read would be silently ignored: the program would
build and run, but never see a key or a line. Rejecting it here, and naming the
subscription that replaces it, turns that silent loss of input into a fix you
can apply directly.

`onKey` is available only in a `Tui` app and `onLine` only in a `Cli` app — each
lives in its own shape's `Sub` module (see IPE-N0035).
