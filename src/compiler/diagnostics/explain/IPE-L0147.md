# IPE-L0147: `Ui.widget` is browser-only and cannot be used outside a Web/WebView shape

`Ui.widget` mounts a **server-driven custom element** — a browser custom element
(a `<my-editor>`-style tag) that you hand a piece of *down* state and a handler
for the *up* events it sends back. It is the seam between your Ipê view and a
JavaScript-defined web component: the down state is serialised out to the
element, and each up event the element emits is decoded back into a message for
your `update`.

That decode is the catch. The up-event payload rides the **seal codec**, the
fail-closed serialisation layer that exists only in a **browser build**. The
`Web` and `WebView` shapes turn it on (they force the runtime's `json` feature);
the `Terminal` and `Program` shapes do not. Outside a browser shape a `Ui.widget`
node would have **no transport for its handler** — an inert element wired to
nothing, a widget with no seam. That is rejected here, at compile time, rather
than emitting Rust that would fail to build after `ipe build` already reported
success.

```ipe ipe:error
-- rejected: `Ui.widget` under `Terminal.appScreen` (no browser custom-element seam)
module Main exposing (main)

import Ipe.Tea.Terminal as Terminal
import Ipe.Ui as Ui exposing (Element)

view : Model -> Element Msg
view model =
    Ui.widget editor model.state FromWidget

main =
    Terminal.appScreen { init = init, update = update, view = view, subscriptions = subs }
```

## How to fix

**Use `Ui.widget` only under a browser shape.** A `Web.app` (or `WebView.app`)
program has the custom-element runtime and the seal codec, so the widget's
up-events decode into your messages:

```ipe ipe:skip
-- accepted: `Ui.widget` inside a `Web.app` view
module Main exposing (main)

import Ipe.Tea.Web as Web
import Ipe.Ui as Ui exposing (Element)

view : Model -> Element Msg
view model =
    Ui.widget editor model.state FromWidget

main =
    Web.app { init = init, update = update, view = view, subscriptions = subs }
```

**If you need this in a terminal app**, build the view from the native `Ipe.Ui`
elements the terminal backend understands — `Ui.text`, `Ui.column`, and the
`Ipe.Input` builders — instead of a browser custom element:

```ipe ipe:skip
-- accepted in every shape: native Ipe.Ui instead of a browser widget
view : Model -> Element Msg
view model =
    Ui.column []
        [ Ui.text "editor:"
        , Ui.text model.state
        ]
```

## Why this happens

The app shapes share one `Element` view type, but each shape can only render the
primitives its runtime backend understands. `Ui.widget` is a browser-backend
primitive: it lowers to a custom-element node whose up-event handler is decoded
through the seal codec. That codec is compiled in only when the browser shapes
force the runtime's `json` feature — a `Terminal` or `Program` build never does.
The compiler proves the shape from the app entry point (`Web.app` / `WebView.app`
versus `Terminal.appScreen` / `Terminal.appLines`) and fails closed the moment a
browser-only node appears in a non-browser build, so an inadmissible widget is a
typed refusal rather than a dead node or a downstream `cargo build` failure.
