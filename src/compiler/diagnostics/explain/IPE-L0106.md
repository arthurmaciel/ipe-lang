# IPE-L0106: top-level function needs a type signature

You defined a top-level function that takes parameters but didn't give
it a type signature. In this version of Sky, a top-level binding with
parameters needs an annotation so the compiler knows the types of its
arguments and result — there's no inference for these yet.

This isn't a problem with the function body; it just needs one line
above it saying what types it works with. Adding the signature is good
practice anyway: it documents the function and pins down its shape.

`[feature: untyped-functions]`

An unannotated function with a parameter trips this:

```sky
increment x =
    x + 1
```

Add a signature naming the argument and result types:

```sky
increment : Int -> Int
increment x =
    x + 1
```

A binding with no parameters doesn't need one in the same way, but
annotating is still encouraged:

```sky
answer : Int
answer =
    42
```

This is a current limitation of the Sky Rust compiler, not a mistake on
your part. If you'd like inference for parameterised top-level
functions, let us know at https://codeberg.org/sky-lang/sky-rust/issues.
