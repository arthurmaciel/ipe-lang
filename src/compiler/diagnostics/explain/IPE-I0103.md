# IPE-I0103: ICE: match arm enum mismatch

Sorry about this — while lowering a `case`, the compiler found a branch whose
constructor belongs to a different type than the value being matched. By the
time a match reaches this stage, type checking should already have ensured
every branch lines up with the type of the thing you're matching on, so a
mismatch here means an internal invariant was broken.

This is a bug in the Ipe Rust compiler, not a mistake in your code. If a real
type error existed — matching a `Light` value against a `Suit` branch, say —
you should have seen a clear type-mismatch message earlier, not an internal
one here.

A match where every branch belongs to the matched type:

```ipe
module Main exposing (main)

type Light
    = Red
    | Green

describe : Light -> String
describe light =
    case light of
        Red -> "stop"
        Green -> "go"
```

A second type, matched consistently against its own constructors:

```ipe
module Main exposing (main)

type Suit
    = Hearts
    | Spades

colour : Suit -> String
colour suit =
    case suit of
        Hearts -> "red"
        Spades -> "black"
```

This is well-typed — branches and value agree — and should compile:

```ipe
module Main exposing (main)

type Answer
    = Yes
    | No

toText : Answer -> String
toText answer =
    case answer of
        Yes -> "yes"
        No -> "no"
```

This is a bug in the Ipe Rust compiler — not your fault. Please report it
(with this source + `ipe version`) at

https://github.com/arthurmaciel/ipe-lang/issues

and we'll track down the inconsistency.
