# IPE-L0149: a Store.select projection is not a usable column reference

`Store.select` projects specific columns of a join. Its lambda receives the two
sides' column records and returns a **column reference** — a bare `side.field`
read on one of those records — or a flat tuple of such references:

```ipe ipe:skip
Store.join books .authorId authors .id
    |> Store.select (\( book, author ) -> ( book.title, author.name ))
    |> Store.selectToList db
```

The compiler reads those references at compile time, checks each field against
its side's row type, derives the validated column names, and sets the SQL
`SELECT` list to exactly those columns. The projection lambda is never run over
real rows, so it must be built from references the compiler can read — not a
computed value.

This error is reported when the projection lambda falls outside that shape.

## Write a column reference, or a tuple of them

The projection body is one `side.field` read on the left or right bound record,
or a flat tuple of such reads:

```ipe ipe:skip
-- one column
Store.select (\( book, _ ) -> book.title)

-- several columns, in order
Store.select (\( book, author ) -> ( book.title, author.name ))
```

## Read the projected columns

Run the projection and decode each column from every returned `Row` by its
position (`0`, `1`, … in projection order):

```ipe ipe:skip
Store.join books .authorId authors .id
    |> Store.select (\( book, author ) -> ( book.title, author.name ))
    |> Store.selectToList db
    |> Task.map
        (List.map
            (\row ->
                ( Store.projReadText 0 row, Store.projReadText 1 row )
            )
        )
```

## What is not accepted

- A **computed** projection (`String.toUpper author.name`, an arithmetic
  expression, a literal): a projection is built only from column references, so
  do the transform in ordinary code after `Store.selectToList`.
- A **nested tuple** element: a multi-column projection is a *flat* tuple of
  `side.field` references; a tuple element cannot itself be a tuple.
- A field the side's row type does not declare, or one whose name is not a valid
  SQL identifier.

## Why this happens

The projected column of a typed `select` is a **checked, closed identifier**
derived from the `side.field` reference at compile time — never a caller-supplied
string, and never a raw value spliced into the SQL text. That is what keeps the
projection injection-safe: a column SQL cannot express has no representation. A
lambda body the compiler cannot read as a column reference is rejected here
rather than emitting a partial statement or a `SELECT *`.

## Glossary

- **column reference** — a bare `side.field` read on a `Cols` record, standing
  for the projected column, not a fetched value.
- **projection** — the `SELECT` list of a query: the specific columns read back.
- **column pushdown** — selecting only the asked-for columns at the database,
  rather than fetching whole rows and discarding fields.
