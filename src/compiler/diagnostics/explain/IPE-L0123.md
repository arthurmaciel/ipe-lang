# IPE-L0123: `Web.route` page builder is not a constructor, lambda, or named function

The second argument to `Web.route` must be one of:

* A page constructor applied to zero arguments (nullary), e.g. `DashboardPage`.
* A page constructor applied to fewer arguments than it needs (partial), e.g.
  `AppDetailPage` when `type Page = AppDetailPage String | ...`.
* An inline lambda, e.g. `\params -> AppDetailPage params`.
* A named top-level function, e.g. `buildPage`.

The Rust backend emits a `move |params| …` closure that type-directs the
`:param` string conversion for each payload slot. A let-bound variable or
computed expression carries no type information the backend can inspect, so it
cannot emit the closure safely.

This trips the gate:

```ipe ipe:error
-- ✘ Let-bound builder — the type cannot be recovered at emit time.
main =
    let myBuilder = AppDetailPage in
    Web.app
        { ...
        , routes = [ route "/apps/:id" myBuilder ]
        }
```

Inline the constructor or lambda at the call site instead:

```ipe ipe:error
-- ✔ Constructor directly.
routes = [ route "/apps/:id" AppDetailPage ]

-- ✔ Inline lambda (useful when you need to reshape the params).
routes = [ route "/apps/:id" (\id -> AppDetailPage (String.toUpper id)) ]
```

A named top-level function is also accepted when every parameter maps to a
supported payload type:

```ipe ipe:skip
-- ✔ Named top-level builder.
buildApp : String -> Page
buildApp id = AppDetailPage id

routes = [ route "/apps/:id" buildApp ]
```

Route payload types must be `String`, `Int`, `Float`, or `Bool`; see
IPE-L0123 (this error) for the full constraint and IPE-L0122 for arity
mismatches.
