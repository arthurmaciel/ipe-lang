# IPE-I0102: ICE: non-exhaustive match

Sorry — the compiler reached a `case` that doesn't cover every constructor,
but it only noticed while building the match's internal form. Missing
branches should be reported to you earlier with a friendly, user-facing
message that names the constructors you still need to handle. Surfacing it
this late means an earlier exhaustiveness check didn't run as intended.

This is a bug in the Ipe Rust compiler, not a mistake in your code. When a
`case` does handle every constructor, it should lower without complaint; if a
genuinely incomplete match gets this far, that gap is ours to close.

A complete match over a two-constructor type:

```ipe
module Main exposing (main)

type Light
    = Red
    | Green

describe : Light -> String
describe light =
    case light of
        Red -> "stop"
        Green -> "go"
```

Every constructor of a larger type covered:

```ipe
module Main exposing (main)

type Direction
    = North
    | South
    | East
    | West

label : Direction -> String
label direction =
    case direction of
        North -> "N"
        South -> "S"
        East -> "E"
        West -> "W"
```

This is exhaustive and should compile — nothing is left out:

```ipe
module Main exposing (main)

type Answer
    = Yes
    | No

toText : Answer -> String
toText answer =
    case answer of
        Yes -> "yes"
        No -> "no"
```

This is a bug in the Ipe Rust compiler — not your fault. Please report it
(with this source + `ipe version`) at

https://github.com/arthurmaciel/ipe-lang/issues

so we can repair the exhaustiveness check.
