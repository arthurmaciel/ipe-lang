# IPE-N0037: a reserved Ipê↔JS boundary type is used before its transport ships

`CustomElement` is a reserved Ipê type that names the typed boundary between an Ipê app and a JavaScript-backed visual widget — a map, a chart, a date-picker. A binding typed `CustomElement down up` names, in its two concrete type parameters, the sealed *down-state* handed to the widget and the *up-event* the widget sends back. Every value crossing that seam is decoded on the way in and encoded on the way out; there is no untyped hole.

The widget transport — the generated glue and the runtime that instantiates the element — is not implemented yet, so an annotation naming `CustomElement` cannot be compiled. It is rejected here rather than silently accepted, because there is deliberately no untyped fallback:

```ipe
module Main exposing (main)

-- rejected: the CustomElement transport is not implemented yet
editor : CustomElement Int String
editor = editor

main = println "hi"
```

The name is *reserved*: you cannot define your own `type CustomElement` to work around this, because that would let an untyped widget slip past the typed seam (a separate rejection, IPE-N0026):

```ipe
module Main exposing (main)

-- also rejected: `CustomElement` is a reserved built-in type name
type CustomElement down up
    = Widget

main = println "hi"
```

Until the transport ships, reach a browser widget you already have through the shipped, typed surface instead — an ordinary element and a typed event handler:

```ipe
module Main exposing (main)

view model =
    Ui.layout [] (Ui.text "a typed view, no untyped widget boundary")

main = Web.app { init = init, update = update, view = view }
```

When the `CustomElement` transport lands, the two type parameters become the enforced contract for the widget: name the down-state and the up-event as concrete declared types, and the compiler generates the encode/decode glue for you.
