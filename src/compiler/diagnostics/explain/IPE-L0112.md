# IPE-L0112: nested constructor payload patterns not supported yet

A constructor pattern bound one of its payload fields with something other
than a plain variable or a wildcard `_`. Matching a constructor and, in the
same step, looking *inside* its payload — a nested constructor, a literal, a
tuple, a record, or a cons pattern — is not supported yet.

For now a payload field is bound to a name or ignored, and any further
inspection happens in a second `case` on the bound name.

## Nested constructor

This peeks inside the `Just` payload with another constructor pattern:

```sky
type Opt a = Som a | Non

firstInt : Opt (Opt Int) -> Int
firstInt o =
    case o of
        Som (Som x) -> x       -- nested constructor payload: not yet
        Som Non -> 0
        Non -> 0
```

Bind the payload to a name, then match it separately:

```sky
type Opt a = Som a | Non

firstInt : Opt (Opt Int) -> Int
firstInt o =
    case o of
        Som inner ->
            case inner of
                Som x -> x
                Non -> 0
        Non -> 0
```

## Variable / wildcard payloads work today

Binding each field to a variable, or ignoring it with `_`, is fully
supported:

```sky
type Pair = Pair Int Int

left : Pair -> Int
left p =
    case p of
        Pair a _ -> a
```

`[feature: nested-payload-patterns]`

This is a current limitation of the Sky Rust compiler, not a problem with
your code. If nested payload patterns matter to your project, please tell
us at https://codeberg.org/sky-lang/sky-rust/issues.
