# IPE-T0002: infinite type

While working out the types in your code, I reached a point where a
type would have to contain itself to make sense — something like
`a = a -> b`, where `a` is both a value *and* a function that takes
that same value, forever. No finite type can satisfy that, so I
stopped and reported it here rather than spinning in circles.

This almost always comes from applying a value to itself, or from a
recursive definition whose pieces don't line up the way you intended.
The fix is usually to add the structure you meant — wrap the recursive
part in its own type, or change how the value is used so it isn't fed
back into itself.

A classic trigger is self-application — passing a function to itself:

```ipe ipe:error
selfApply f =
    f f
```

For `f f` to type-check, `f` would have to be both the function and
its own argument, which needs an infinite type. Give `f` something
else to act on instead:

```ipe
applyTo : Int -> (Int -> Int) -> Int
applyTo x f =
    f x
```

The same trap appears when a definition refers to itself in a way that
makes its type grow without end:

```ipe ipe:error
loopy x =
    loopy
```

Here `loopy` returns `loopy`, which returns `loopy`, and the type
never settles. Decide what the function should actually produce and
return a concrete value:

```ipe
countDown : Int -> Int
countDown n =
    if n == 0 then
        0

    else
        countDown (n - 1)
```
