# IPE-T0004: more parameters than the type signature describes

You gave a binding a type signature, and then defined it with more
parameters than that signature has room for. The annotation describes
a value that takes a certain number of arguments, but the definition
binds more names than that — so the extra parameters have no type to
stand on, and I can't reconcile the two.

Each `->` in the signature is one argument the value accepts. If the
definition's left-hand side lists more parameter names than there are
arrows, either the signature is missing some arrows, or the definition
has parameters it shouldn't.

Here the signature says `Int` — a plain value, no arguments — but the
definition takes two:

```ipe ipe:error
f : Int
f a b =
    a + b
```

If `f` really is meant to take two `Int`s and add them, the signature
needs two arrows:

```ipe
f : Int -> Int -> Int
f a b =
    a + b
```

The mismatch can also be off by just one. Here the signature describes
a one-argument function, but the body binds two parameters:

```ipe ipe:error
addOne : Int -> Int
addOne x y =
    x + y
```

If `addOne` should only ever add one to its argument, drop the extra
parameter so the definition matches the annotation:

```ipe
addOne : Int -> Int
addOne x =
    x + 1
```
