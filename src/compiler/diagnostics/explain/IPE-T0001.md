# IPE-T0001: type mismatch

I was checking your code and found two types that have to agree, but
don't. One part of the program promises a value of one type, and
another part hands it a value of a different type. Both can't be right
at once, so I stopped here to point out exactly where they clash.

When I can, I show you the type I *expected* at this spot and the type
I actually *found*, side by side. If the mismatch is buried inside a
record or a deeper structure, I name the field or the path that
diverges, so you don't have to hunt for it.

Here a function annotated to return a `String` returns an `Int`
instead:

```ipe ipe:error
greeting : String
greeting =
    42
```

The body `42` is an `Int`, but `greeting` is declared to be a
`String`. Either fix the annotation or fix the body — here we give it
the text it claims to produce:

```ipe
greeting : String
greeting =
    "hello"
```

Mismatches also show up at call sites, where an argument's type
doesn't fit the parameter it's being passed to:

```ipe ipe:error
double : Int -> Int
double n =
    n + n

result : Int
result =
    double "five"
```

`double` wants an `Int`, but `"five"` is a `String`. Pass it a number:

```ipe
double : Int -> Int
double n =
    n + n

result : Int
result =
    double 5
```
