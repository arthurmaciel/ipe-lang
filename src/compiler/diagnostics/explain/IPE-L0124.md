# IPE-L0124: `Web.app` routes list is non-empty but Model has no `page` field

**This is a warning, not an error — the program still compiles and runs.**

`Web.app` supports two modes, chosen automatically by the compiler:

* **Non-routed** — the Model has no `page` field; `routes` and `notFound` are
  structurally required fields but are not forwarded to the runtime. Every URL
  serves the same app.
* **Routed** — the Model has a field named exactly `page`; the runtime calls
  `live_app_routed` and uses `routes` / `notFound` to dispatch incoming URLs
  into that field.

The routed-page field name is a **fixed convention: it must be spelled
`page`**. The compiler detects routing by looking for a `page` field on the
Model type (recovered from the `view` function's first parameter).

This warning fires when `routes` is non-empty but the Model has **no `page`
field**. The most common cause is a mis-named field — e.g. a Model with
`currentPage` or `route` instead of `page`. Because the field name does not
match the convention, the routes are forwarded to the non-routed path and never
update the Model: all URLs serve the same page, silently.

To route, name the field exactly `page`:

```ipe
type Page = HomePage | AboutPage | BlogPage String

type alias Model =
    { page : Page          -- must be `page`, not `currentPage` / `route`
    , ...
    }

main =
    Web.app
        { init = init
        , update = update
        , view = view
        , subscriptions = subscriptions
        , routes =
            [ route "/" HomePage
            , route "/about" AboutPage
            , route "/blog/:slug" BlogPage
            ]
        , notFound = HomePage
        }
```

If you genuinely do not want routing, use an empty `routes` list and the
warning disappears:

```ipe
main =
    Web.app
        { ...
        , routes = []
        , notFound = HomePage
        }
```

The shape that triggers this warning — a non-empty `routes` list with a
mis-named (or absent) `page` field:

```ipe
-- ⚠ `currentPage` is not `page`, so routing is silently disabled.
type alias Model = { currentPage : Page }

main =
    Web.app
        { ...
        , routes = [ route "/" HomePage ]  -- <-- warns: routes ignored
        , notFound = HomePage
        }
```

## Why a warning, not an error

Go's reference runtime (`applyRoute` → `RecordUpdate(model, {"Page": page})`)
silently no-ops when the Model has no `Page` field, so this shape compiles
there. Ipe matches that behaviour to stay a superset of the reference — but
surfaces the warning because a non-empty `routes` list with no `page` field is
almost always an unintended mistake, not a deliberate non-routed app.
