# IPE-N0013: type alias applied with the wrong number of arguments

A parametric `type alias` has to be applied to exactly as many type arguments as it declares parameters. The alias is *expanded* — each parameter is replaced by the matching argument and the result is spliced in where you wrote the alias — so a missing or extra argument leaves the substitution undefined. I point at the annotation that misapplies the alias.

A one-parameter alias declares a single hole:

```sky
type alias Pair a =
    ( a, a )
```

Apply it to one type argument and it expands cleanly — `Pair Int` becomes `( Int, Int )`:

```sky
type alias Pair a =
    ( a, a )

addPair : Pair Int -> Int
addPair p =
    if p == ( 20, 22 ) then 42 else 0
```

Giving too many arguments — or too few — is the error. `Pair Int Bool` supplies two arguments to a one-parameter alias, and a bare `Pair` supplies none; both are rejected. Drop the surplus argument (or add the missing one) so the count matches the parameter list:

```sky
type alias Pair a =
    ( a, a )

-- error: `Pair` takes 1 type argument, but 2 were given
bad : Pair Int Bool -> Int

-- fixed: exactly one argument
good : Pair Int -> Int
```
