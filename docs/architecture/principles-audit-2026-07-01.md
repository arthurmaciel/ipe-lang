## Per-partition summaries

### sky_parse (2)

Audited the sky_parse partition (lexer.rs, layout.rs, lib.rs [non-test lines 1-33 only], parser.rs) against all six principles in order. SECURITY: clean — pure lexer/parser with no injection/secret/auth/path sink; the one security-relevant property (stack-overflow via adversarial nesting) is correctly closed by the MAX_DEPTH=256 depth guard threaded through every recursive production, and all loops make token progress so no unbounded memory/CPU. CORRECTNESS: clean — exhaustive tok_kind/peek_binop, fail-closed catch-alls, deliberate no-float-pattern soundness gate, span-adjacency-based negative-literal rule. SOUNDNESS: no reachable panic — #![forbid(unsafe_code)], zero non-test unwrap/expect, guarded rfind, checked_neg fail-closed, wrapping_neg on a lex-bounded magnitude is provably exact, span_merge is overflow-free via min/max. Two LOW findings only: (1) two raw u32+char_width span additions in the lexer deviate from the file's own saturating_add convention (debug-overflow only at a practically-unreachable >4GiB offset); (2) the closed 17-operator set is discarded into an interned Symbol in Expr_::Binops instead of a typed BinOp enum, a make-invalid-states-unrepresentable gap that forces downstream string re-matching (AST type is in sky_syntax and may be intentional reference-parity). No critical/high/medium issues; the partition is close to clean and the strict principle ordering is respected throughout. No rewrite-opportunity items beyond finding (2), which is the only legacy stringly-typed shape worth reworking toward an ADT.

### sky_canon (5)

sky_canon is a well-hardened name-resolution crate: forbid(unsafe_code), no non-test unwrap/expect/panic/raw-index, fail-closed Diagnostics for every unresolved/duplicate/arity case, deterministic BTreeMap + name-sorted output, and a cycle-guarded alias expander. No injection/secret/XSS surface exists at this stage (no SQL/shell/HTML emitted). 5 findings, all design-level: 1 medium (exponential alias-expansion DoS — the existing `visited` guard stops cycles but not fan-out doubling, a real compile-time amplification when a toolchain builds untrusted source), and 4 low (silent shadowing not diagnosed; SqlValue ctor-index↔backend-enum coupling held only by a comment; unbounded recursion → stack-overflow abort on pathological nesting; `Symbol::from_raw(0)` sentinel on unreachable fallbacks instead of a CompilerBug). No reachable panic from well-typed Sky, no exit-0-then-cargo-fail shape, no unsafe.

### sky_types (3)

Audited crates/sky_types/src/{constrain,solve,exhaust,unionfind,lib}.rs (non-test). The union-find, solver, and exhaustiveness passes are exemplary: iterative traversals (no native-stack growth), every arena/index access goes through .get()/split_first()/checked_sub(), all internal-invariant violations map to Diagnostic::CompilerBug rather than panics, and DOS/adversarial input is bounded (Budget step cap, ZONK_NODE_LIMIT, WITNESS_CAP). #![forbid(unsafe_code)] holds; no reachable unwrap/expect/panic/raw-index in non-test code. Security: the type checker is compile-time only; it correctly upholds the SQL parse-don't-validate boundary (Db.exec/query take typed List SqlValue, unsafeFindWhere carries its List String binding channel, execRaw is the documented raw hatch) — no injection/secret surface here. ONE real soundness breach found: the SKY-T0014 equality gate (ty_is_equatable) admits opaque runtime type constructors (Task/Db/Decoder/Cmd/Sub/Request/Response/Route/Cookie) as PartialEq-deriving, but their emitted Rust reps do not derive PartialEq (verified: SkyTask = Pin<Box<dyn Future>>), so `==`/`/=` on such a value type-checks then fails cargo — exactly the exit-0-then-cargo-fail class the gate exists to close. Two low-severity notes on silent fallbacks. Not manufacturing filler: the partition is otherwise clean.

### sky_backend_rust (4)

Audited crates/sky_backend_rust/src/{lib,emit_types,emit_expr,naming,project,preamble}.rs (Sky IR → Rust codegen). SECURITY: clean. This crate is a code generator, so its security boundary is "the emitted Rust must be safe" — and it holds. String/char literals are emitted via Rust's `{:?}` Debug form, which produces a deterministic, fully-escaped, valid Rust literal (no code injection possible). SQL is handled correctly: DbExec/DbQuery route to the PARAMETERIZED `db_exec_params`/`db_query_params` with `SqlValue`→`SqlParam` projection; DbExecRaw/DbUnsafeFindWhere are the documented raw escape hatches that pass Sky expressions straight through (parameterization is the runtime's job, not codegen's). No header/CSS/log/path injection is introduced. Identifiers are Sky-lexer-constrained and keyword-mangled (`mangle_reserved` uses the universally-valid trailing-underscore form, covering crate/self/Self/super). `#![forbid(unsafe_code)]` at the crate root covers every module; no unwrap/expect/raw-index in non-test code; all slice access is `.get()`/`.first()` checked; arithmetic uses `saturating_add`; MAX_EMIT_DEPTH=96 fail-closes a deep IR spine before native stack overflow. CORRECTNESS/COMPLETENESS: kernel_name is exhaustive over KernelFn (no `_` catch-all); the emit_*_call dispatchers use explicit variant lists + fail-closed `_ if k.is_db()/is_tea()/is_server()` guards so a newly-wired kernel is a compile error, not a silent miss — a genuinely good design. Findings are limited to a few DESIGN-level two-rules gaps and low-severity residual hazards; none are critical/high. A clean security result here is the honest verdict.

### runtime (2-rules + drift) — runtime/src/sky_runtime/{db.rs, server.rs, task.rs, server_stream.rs, live/pubsub.rs} (3)

Audited the runtime partition (db.rs/SqlValue, server.rs accessors+adapter, task.rs, server_stream.rs, live/pubsub.rs) against all 6 principles in order, with the two rules and security as emphasis. The partition is strongly hardened and the previously-vetted 2026-06-30 guards all hold: SQL values are always positional-bound (never interpolated); table/column names are identifier-validated before interpolation; unscoped UPDATE is refused fail-closed; the RETURNING projection is validated; withTransaction is RAII-safe with fail-closed sole-ownership; cookies are CRLF/attribute-sanitised and Secure-in-prod; X-Forwarded-For is trusted only opt-in (no IP-spoof rate-limit bypass by default); the WS origin allowlist is hardened against CSWSH glob bypass; oversize bodies 413 rather than silently truncate; the streaming sentinel is per-process-nonce-protected against forgery and never leaks the nonce. No reachable panic/unwrap/expect/raw-index/as-narrowing/overflow in non-test code — status casts clamp before `as u16`, retry backoff uses saturating arithmetic with a 30s cap, all Mutex locks are poison-tolerant, the pubsub TypeId-broker downcast rebuilds-not-panics. No unsafe (crate is forbid-unsafe). Three non-blocking design findings: (1) MEDIUM — db.rs has two divergent SQL-identifier validators (`SqlIdent` newtype vs bool `valid_sql_ident`, differing on `.`), with the newer field kernels re-validating-then-interpolating a raw String instead of parsing through the existing newtype (parse-don't-validate regression + a getById-vs-insertFields consistency divergence; not a security hole, both charsets are injection-safe). (2) LOW — server_redirect/server_with_header inject caller strings into headers with no boundary sanitisation, relying implicitly on the http crate to reject CRLF (fail-closed to 500; safe but undocumented and dependency-dependent). (3) LOW — streaming responses are smuggled through the buffered body String via a magic prefix (a make-invalid-states gap, constrained by codegen), and the `pending_handlers` map leaks a handler Arc if a handler calls Stream.stream but returns a different response (unbounded, app-triggered).
