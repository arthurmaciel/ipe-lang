# `ipe package audit` — Tier-2 capability-exercise harness

Status: design (tbd). Specifies the ADMITTING path of Tier-2 native-code
enforcement: the per-package harness that drives a native-bearing package's
*own* generated FFI bindings under a declared-scoped jail, so the differential
confinement reconciler ([`audit_native::reconcile_native`]) observes the
package's real capability behaviour and Tier-2 can construct
[`Tier2Outcome::Certified`] instead of only rejecting native packages
fail-closed.

Extends the campaign design
(`docs/architecture/tbd/audit-tier2-native-enforcement-design.md`) and
`docs/adr/0046-tier2-differential-confinement.md`. Reuses the shipped build-jail
outcome primitive (`src/compiler/sandbox/src/build_jail.rs`) and the shipped
reconciler + wiring (`src/ipe-cli/src/audit_native.rs`). Fenced blocks are
illustrative unless the prose says a fixture ran; no fenced block in this doc is
a runnable command a reader should copy.

---

## 0. The gap this closes

The build-jail primitive is a *returning* jail whose outcome is a typed
`JailOutcome`, admit-eligible only on positive proof of a clean exit
(`build_jail.rs`, `JailOutcome::decode`). The differential reconciler
`reconcile_native` — proven end-to-end against the real jail — and the
child-of-wrapper `ProbePayload`, the `WrapperScan` static cross-check, and
`scoped_profile` single-sourcing the confinement are all shipped. But
production `native_tier2` (`audit_native.rs:544`) still rejects every
native-bearing package as `no_probeable_entrypoint()`, because **nothing drives
the package's own native code through the reconciler**. The existing probe
fixture (`tests/fixtures/admission/untrusted-build.sh`) exercises *fixed
stand-in actions* — a Python socket connect, a write to `$ESCAPE_PATH` — chosen
by us, not by the package. Certifying on that would be exactly the false clean
the seal forbids: a stand-in whose actions Tier-2, not the package, chose.

This design answers the one open question: **how does a real package's native
FFI code get exercised, under the jail, so its capability behaviour is
observable and the reconciler's `Clean` is a fact about the package's code.**

## 1. What "exercising the package's native capabilities" is

### 1.1 The options weighed

| Option | Mechanism | Verdict |
|---|---|---|
| (a) drive declared FFI entry points with synthesised inputs | fabricate arguments to each bound `Rust.*` fn and call it | **Rejected as the sole mechanism.** Cannot synthesise a valid `FirestoreDb` handle or a `stripe::Client`; most bindings take opaque constructed receivers. Fabrication either fails to compile or calls with a null-ish stand-in whose effect is unrepresentative. It also runs arbitrary author code to completion — unbounded. |
| (b) build-time-only observation | does linking/building the crate under the axis-scoped jail already demand an axis? | **Adopted as the FLOOR, not the whole.** A `build.rs` or proc-macro that reaches the network/filesystem at build time is a real capability demand, observed by building the crate as the jail's untrusted child. But building alone does not exercise *runtime* FFI capability, so it under-observes. It is sound (only ever rejects, per §3) and is the always-available lower bound. |
| (c) run the package's own test/e2e harness under the jail | drive a package-declared `e2e.json` / test entry | **Rejected.** No such capability-probe entry exists in the package model today, and inventing an author-authored probe re-introduces the trust problem: the author controls what it exercises, so an under-exercising probe launders an undeclared axis past the check. An author-owned entry can never own the *exercise*, only the *build*. |
| (d) a generated per-crate probe that references each surviving bound `Rust.*` fn | emit, from the package's *own* inspected bindings, a `main` that references every surviving wrapper so the linker retains it and any build-time reach is exercised | **Adopted as the exercise driver.** The probe is **generated by us from the package's own bindings**, not authored by the package, so the package cannot shrink the exercised surface; and it observes the package's real code, not a stand-in. Its coverage limit (build+link reach, not arbitrary runtime paths) is stated honestly (§4). |

### 1.2 The chosen mechanism: a generated link-reachability probe over the package's own bindings

The exercise is **(b) ∪ (d)**: build the package's emitted native crate as the
untrusted child of the wrapper, with a **generated probe `main` that references
every surviving bound wrapper function** (`bindings.rs`'s `surviving_ref_names`
is the exact DCE survivor set) so the linker cannot dead-strip the FFI surface,
then observe — by differential confinement — whether producing that fully-linked
artifact demanded a withheld axis.

Concretely the untrusted child is a `cargo build` of an emitted crate whose
`src/main.rs` is generated to take the address of (never *call* with fabricated
inputs) each surviving wrapper:

```rust
// ILLUSTRATIVE (not runnable) generated probe main — references, does not
// invoke, each wrapper so the linker retains the whole FFI surface and any
// build.rs / proc-macro / link-time capability reach is exercised, without
// running author logic to completion on fabricated inputs.
fn main() {
    let keep: &[*const ()] = &[
        crate::ffi::the_slug::the_first_wrapper_ref_name as *const (),
        crate::ffi::the_slug::the_second_wrapper_ref_name as *const (),
        // … every name in surviving_ref_names(pkg), sorted
    ];
    std::hint::black_box(keep);
}
```

**Why this is the sound reading of "exercise the package's own code":**

- The referenced set is `bindings::surviving_ref_names(pkg)` — the *same*
  survivor gate the interface emitter keys off (`bindings.rs`, `surviving_ref_names`),
  so the probe's surface is exactly the package's real, emitted FFI surface and
  cannot drift from it (single source of truth). The package cannot author a
  narrower probe.
- Taking a function address forces the linker to retain the wrapper and its
  transitive `krate::…` call, so a native dependency whose *build* (`build.rs`,
  proc-macro, linker script, `bindgen` fetch) reaches the network or writes
  out-of-scratch trips the jail — the build-time capability floor (b).
- It deliberately does **not** invoke the wrappers with fabricated inputs. That
  avoids both the fabrication-impossibility of option (a) and running unbounded
  author logic. The honest coverage statement (§4) records that runtime-only
  capability reach (an axis a wrapper touches only when *called* with real data)
  is **not** observed by this cut and therefore keeps the verdict conservative.

The one-line soundness reason: **the probe references the package's own
DCE-survivor wrapper set, so what is built and confined is the package's real
native surface — never a stand-in whose actions Tier-2 chose.**

## 2. Child-of-wrapper wiring

The untrusted build must never own `exit(0)`. The wiring reuses the shipped
`ProbePayload::wrapper_owned` (`audit_native.rs:145`) unchanged; this design
only specifies what fills its `untrusted_build` tail — which today is
`Vec::new()`.

```text
ILLUSTRATIVE argv layout (not a runnable command):
argv = [ /usr/bin/env PROBE_MODE=tier2 TIER2_AXIS=<sel> SCRATCH_DIR=… ESCAPE_PATH=… /bin/sh ]
       ++ [ <wrapper.sh> ]                      # exit-owning, authored by us
       ++ [ <untrusted_build…> ]                # the package's cargo build, wrapper's CHILD
```

- The **wrapper** is our authored script (the production sibling of
  `untrusted-build.sh`, `PROBE_MODE=tier2`). It runs the untrusted `cargo build`
  **as its child**, captures the child's exit, and translates a capability
  denial observed during that child's execution into the wrapper-owned per-axis
  exit code (`AXIS_EXIT_NETWORK=10` / `AXIS_EXIT_FILESYSTEM=11`,
  `build_jail.rs:54`). The child's own exit code is subordinate: a child that
  `exit(0)`s while a withheld axis was denied still yields the wrapper's denial
  code, because the denial is the wrapper's signal, not the child's stdout.
- `ProbePayload` structurally forbids inverting the order — there is no
  constructor placing the untrusted build ahead of the wrapper
  (`audit_native.rs:131`), so no call site can let the package own the exit the
  decoder reads.
- The exercise driver (the generated probe `main`) is emitted **into the crate
  the child builds**, not into the wrapper. So the wrapper stays the trusted,
  fixed exit-owner; the untrusted, generated-from-package material is confined to
  the child's build. The wrapper never trusts anything the child wrote.

**The wrapper's tier2 denial signal for a real build.** A fixed axis probe on the
FULL declared-scoped run is unsound: a socket / out-of-scratch write the wrapper
performs unconditionally *fabricates* a capability demand the package never made,
so no declared set other than `{network, filesystem}` could ever certify (a
benign `[network]`-only package's fixed filesystem probe is denied → reject). The
sound signal splits by run:

- **Full declared-scoped run (`TIER2_AXIS=none`): child-exit-only, NO fixed axis
  probe.** A withheld axis is withheld by capability *removal* (the net namespace
  is unshared; the escape path is not bound writable), so a build that reaches it
  is killed / errors → the child's non-zero exit decodes to `BuildFailed`. A build
  that *caught* the denial and exited anyway performed **no effect** (a caught
  denial is a no-op), so the child's clean exit is positive proof it reached no
  withheld axis → `Clean`. The child build is a fixed `cargo build` of a probe
  crate whose `main` we generate (address-of refs, no author `main`), so the
  untrusted crate cannot own this exit's meaning. Used-but-undeclared thus
  collapses into build-fails-in-jail on the full run: both reject, only the
  diagnostic differs (axis naming is traded for not fabricating a demand). A
  non-zero child with no axis probe run maps to a distinct non-per-axis exit
  (`TIER2_EXIT_BUILD_FAILED`, decoded `BuildFailed`) — the load-bearing hinge: the
  wrapper never exits clean when the child build failed.
- **Tightening run (`TIER2_AXIS=<the one withheld axis>`): the single-axis fixed
  probe.** Here the axis is one the author *declared*, so probing it fabricates no
  demand: the run can only *keep* the axis (probe denied → axis needed) or reject,
  never certify. This is the legitimate, bounded use of the fixed probe.

## 3. The ADMIT fail-closed matrix — exact `Certified`-construction precondition

`Tier2Outcome::Certified { platform: CERTIFIED_PLATFORM }` may be constructed
**iff every one of these holds**, and the construction lives at exactly one call
site in `native_tier2` (`audit_native.rs:544`):

1. `is_native_bearing(declared, has_rust_deps)` is true (a pure package is
   `SkippedPureIpe`, never `Certified`).
2. The host is `linux-x86_64` (the one wired platform, `CERTIFIED_PLATFORM`).
   Any other platform: the local run prints a pre-flight note and returns a
   non-certifying outcome; only the CI matrix on a wired platform can admit
   (campaign §2.1). A non-Linux host **never** constructs `Certified`.
3. The emitted native crate + generated probe `main` were produced from the
   package's own inspected bindings, and `surviving_ref_names(pkg)` was
   **non-empty** — there was a real FFI surface to exercise. An empty survivor
   set is *un-exercised* → reject (`no_probeable_entrypoint`, kept), never a
   vacuous clean.
4. The jail was **established** (`JailOutcome::Unavailable` on the
   declared-scoped run → `sandbox_unavailable` reject, never a skip on Linux).
5. `reconcile_native(declared, &JailProbeRunner{…, untrusted_build: <REAL cargo
   build of the emitted crate>}, &WrapperScan::over_package(root)?, &scoped)`
   returned `Ok(())` — i.e. the declared-scoped run was `JailOutcome::Clean`
   **and** the tightening pass found no axis both removable *and* statically
   unreached. The `untrusted_build` passed to the runner is the package's REAL
   build, never `Vec::new()` (the seal from the sub-PR 2 review).

Every non-admit branch is a typed `Rejection` carrying `Check::NativeTier2`, or a
recorded platform-skip. The matrix (unchanged from the campaign design, now with
the exercise driver filled in):

| Situation | Verdict | Where |
|---|---|---|
| pure Ipê package | `SkippedPureIpe` | `native_tier2`, Tier-1 still gates |
| empty FFI survivor set (nothing to exercise) | **REJECT** (`no_probeable_entrypoint`) | fail-closed, never vacuous clean |
| declared-scoped run `Denied{axis}` | **REJECT** used-but-undeclared | `reconcile_native` §1 |
| declared-scoped run `BuildFailed` | **REJECT** build-fails-in-jail | `reconcile_native` §1 |
| declared-scoped run `Unavailable` | **REJECT** sandbox-unavailable (the platform) | `reconcile_native` §1 |
| tighten stays `Clean` with axis removed **and** static scan agrees unreached | **REJECT** declared-but-unused | `reconcile_native` §2 |
| tighten `Denied{other-axis}` | **REJECT** ambiguous-tighten (fail-closed) | `reconcile_native` §2 |
| non-Linux / unwired platform | non-certifying note, **never** `Certified` | `native_tier2` |
| flaky / non-deterministic exercise | **REJECT** (§5) | never flaps to admit |
| declared-scoped `Clean` ∧ no removable-and-unreached axis ∧ non-empty surface ∧ Linux | **CERTIFY** | the one admit path |

There is no warn-and-pass row and no second `Certified` construction site.

## 4. Coverage honesty

The exercise is **build+link reachability**, not arbitrary runtime intent. The
honest surface must state exactly this, and must never overclaim:

- On a genuine certify, the passing line names the platform and the coverage it
  actually proved: e.g. `Tier-2 native check passed on: linux-x64 (build+link
  reachability of N FFI bindings under a declared-scoped jail)`. It does **not**
  say "all capability paths verified".
- The `native-ffi` deferral note (`audit.rs`) is *narrowed* to unwired
  platforms, never dropped wholesale (campaign §3.2, monotone rollout).
- The certify record carries the exercised surface size (`surviving_ref_names`
  count) so a reader can see what breadth was covered.
- The documented limit (also in the reject diagnostics and ADR 0046): a
  capability a wrapper reaches **only when invoked with real runtime data** is
  *not* exercised by this cut and therefore is not observed. This is safe because
  (i) the shipped artifact is still confined to the *declared* set at `ipe run`
  by the runtime jail (ADR 0040), so an undeclared-but-present axis is denied at
  run regardless; and (ii) the differential observation only ever over-rejects,
  never over-admits (ADR 0046). An author is never told "clean" means "no
  capability anywhere" — only "no withheld axis was demanded to build and link
  this native surface".

## 5. Determinism / non-flakiness

A certify/reject verdict must be reproducible; a flaky exercise must fail-closed,
never flap to admit.

- **No network in the exercise itself.** The generated probe `main` references
  wrappers; it does not connect anywhere. The *only* network reach that can occur
  is a native dependency's own build-time fetch — which is exactly a capability
  demand we *want* to observe as a denial under a network-withholding jail. Crate
  sources are vendored/pre-fetched before the jailed build, so an ordinary `cargo
  build` does not itself need the network; a build that *does* is a genuine,
  deterministic used-but-undeclared signal, not flake.
- **Seeded, input-free exercise.** Because the probe takes addresses rather than
  invoking with fabricated data, there is no RNG, no clock-dependent branch, no
  input to seed — the build+link outcome is a deterministic function of the
  (pinned) dependency set and the profile.
- **Bounded, killed-not-hung.** The jail's wall-clock + resource caps
  (`SandboxProfile.limits`, `run_jail.rs`) bound the O(axes) tightening builds; an
  untrusted `build.rs` that spins is killed by the cap and decodes to
  `BuildFailed` (`decode(None)` → `BuildFailed`, `build_jail.rs:161`), a reject —
  never a hang, never a clean.
- **Ambiguity is reject.** `decode` folds every unrecognised exit, signal, or
  no-exit into `BuildFailed` (`build_jail.rs:174`); a tightening denial naming the
  wrong axis is `ambiguous_tighten` (`audit_native.rs:317`). No nondeterministic
  outcome can reach `Clean`.
- **Repeat-to-confirm (recommended).** Where a platform's jail is cheap enough,
  run the declared-scoped `Clean`-eligible run twice and require both `Clean`; a
  disagreement is `BuildFailed`/reject. This turns residual nondeterminism into a
  reject rather than a coin-flip on admit. Optional; the cap + fixed decode
  already prevent a flap *to* admit.

## 6. PRINCIPLES analysis (precedence order)

1. **Security (highest).** The exercise driver is generated *by us* from the
   package's own DCE-survivor set — the package cannot narrow the exercised
   surface to launder an axis. The untrusted build is always the wrapper's child
   (`ProbePayload`), so it never owns the admit-deciding exit. Every uncertain
   branch rejects (empty surface, unavailable jail, ambiguous tighten, flake,
   non-Linux). The observation over-rejects by construction (ADR 0046), so no
   undeclared axis slips through as "not observed". The generated probe does not
   invoke wrappers with fabricated inputs, so it cannot be tricked into
   *exercising* an attacker-chosen effect — it only forces linkage.
2. **Correctness.** The exercised surface is `surviving_ref_names(pkg)`, the same
   set the interface emitter uses — Tier-2's exercise and the shipped binding
   surface cannot diverge (single source). The declared-scoped profile is the
   same `profile_from_capabilities` the runtime jail uses (`scoped_profile`,
   `audit_native.rs:212`), so confinement cannot drift. The admit predicate is one
   total conjunction over `JailOutcome` at one site.
3. **Soundness.** No new panic surface on the audit path: `JailOutcome` /
   `RunJailDefect` are propagated with `?`; the generated probe uses `black_box` +
   address-of, no index/unwrap/cast. The sole `unsafe` remains the shipped
   `OwnedFd::from_raw_fd` memfd ownership (`build_jail.rs:234`, already reviewed,
   fd-leak fixed). `native_tier2` stays unwrap-free.
4. **Efficiency.** Yielded to Security: generating the probe + the O(axes)
   tightening builds cost extra confined compiles. Bounded (≤ 2 tightenable axes
   here; the jail caps wall-clock/resources). Optional skip of a redundant tighten
   when the static scan already proves the axis reached — never grounds to admit.
5. **Completeness.** Yielded: only `linux-x64` certifies; build+link coverage is
   less than a true tracer's. Both gaps are stated (§4, ADR 0046), tracked, and
   safe (only over-reject).
6. **Readability.** The exercise driver is one generated file mirroring the
   existing binding emitter's survivor gate; `native_tier2` keeps the shipped
   `NativeAudit` shape and one admit site.

## 7. Implementation + verification plan

### 7.1 Files

- **`src/compiler/ffi/src/bindings.rs`** (or a new sibling `probe.rs`) — a
  `emit_capability_probe_main(pkg) -> String` that references every
  `surviving_ref_names(pkg)` wrapper via address-of + `black_box`. Reuses the
  existing survivor gate; adds no new trust surface (reads only the inspected
  `PkgInfo`). Emit nothing (→ empty-surface reject) when the survivor set is
  empty.
- **`src/ipe-cli/src/audit_native.rs`** — `native_tier2` (`:544`) stops returning
  `no_probeable_entrypoint()` unconditionally: it builds the emitted native crate
  + generated probe into the audit scratch dir, constructs a `JailProbeRunner`
  whose `untrusted_build` is the **REAL** `cargo build` argv of that emitted crate
  (never `Vec::new()`), runs `reconcile_native`, and — on `Ok(())` with a
  non-empty surface on Linux — constructs the **first** `Tier2Outcome::Certified`.
  `no_probeable_entrypoint` is *kept* for the empty-surface / non-native-probeable
  case.
- **`src/ipe-cli/src/audit.rs`** — consume the real `Tier2Outcome::Certified` in
  the honest surface: emit the platform + coverage-scoped passing line (§4);
  narrow (never drop) the deferral note.
- **`tests/fixtures/admission/untrusted-build.sh`** — extend the tier2 wrapper to
  run its `untrusted_build` tail (the real `cargo build`) as its child *before*
  the fixed axis probe, so the wrapper's per-axis exit still owns the signal for a
  real build (§2). Keep the exit-code contract byte-identical.
- **A production wrapper** (the sibling of the fixture, shipped, not a test
  fixture) if the audit path must not depend on a `tests/` file — the fixture
  proves the contract; production ships an equivalent script under a non-test
  path, asserted equal to the fixture by a test (SSOT).
- **`docs/adr/`** — no new ADR; 0046 already records the model. Update the
  campaign design's §6 decomposition to mark this sub-PR done.

### 7.2 Mandatory fixtures (positive + negative controls)

- **POSITIVE — genuine certify:** a purpose-built native fixture crate (or a
  reduced `13-skyshop`) that declares exactly the axes its native surface demands
  at build+link time, whose emitted probe references its survivors, builds clean
  under the declared-scoped jail, and has no removable-and-unreached axis →
  `Tier2Outcome::Certified { platform: "linux-x64" }`. This is the *first* genuine
  `Certified` construction and MUST be driven end-to-end through the REAL jail
  (gated `IPE_E2E=1`, like the shipped `build_jail_e2e.rs`), not a scripted
  runner.
- **NEGATIVE — used-but-undeclared at the OS boundary (the standing red
  canary):** a native fixture that declares `[capabilities] = []` (or only
  `clock`) but whose native build/link genuinely reaches the network or writes
  out-of-scratch. Under the declared-scoped jail the wrapper's post-build probe is
  denied → `Denied{axis}` → `Check::NativeTier2` reject naming the axis. This MUST
  stay red if the admit predicate ever regresses; wire it as a standing CI canary
  (campaign §5.2). It must reject **at the OS boundary** (a real jail denial), not
  merely at a scripted-runner level.
- **NEGATIVE — declared-but-unused:** declares `network`, native surface never
  reaches it, static scan agrees → tighten removes `network`, stays clean → reject
  over-broad.
- **NEGATIVE — empty-surface:** a native-bearing package whose survivor set is
  empty → `no_probeable_entrypoint` reject (never vacuous clean).
- **NEGATIVE — sandbox-unavailable:** simulate a missing primitive on Linux →
  reject the platform, not skip.
- **POSITIVE control (isolation is real):** reuse the enforce/control fixture
  duality so a "clean" Tier-2 result can never be a false pass from a broken jail.
- **Pure-Ipê:** `SkippedPureIpe`; Tier-1 still fully gates.
- **13-skyshop:** as an integration target, either genuinely certifies (if its
  native build reaches no undeclared axis under its declared set) or rejects
  honestly — never silently admitted. Because its dependency tree (six
  async-stripe crates + firestore + firebase) is heavy, the CI fixture may use a
  reduced purpose-built crate for the always-run canary and reserve full
  13-skyshop for the slow examples sweep.

### 7.3 Verification

- `cargo nextest run -p ipe-cli` + `-p ipe-sandbox` (scripted-runner matrix +
  decode tests, already green).
- `IPE_E2E=1` end-to-end: the positive certify fixture and the red-canary fixture
  through the REAL bwrap jail (extend `build_jail_e2e.rs` or a new
  `audit_native_e2e.rs`). The canary proves a real OS-boundary denial; the
  positive proves the first genuine `Certified`.
- clippy `--all-targets -D warnings -W clippy::pedantic` clean on the touched
  crates.
- No full example/perf sweep locally (per project constraint); push and let CI run

## 8. One sub-PR or a sub-campaign?

**One sub-PR** — the third and last campaign sub-PR needed to make Tier-2 *admit*
on Linux. It is bounded: one generated-probe emitter, the `native_tier2` wiring
change (fill the `untrusted_build` tail + construct the first `Certified`), the
honest-surface line, and the fixtures. It reuses the already-shipped,
already-reviewed jail primitive (build-jail) and reconciler (`audit_native`)
unchanged. The later platforms (macOS / Windows / FreeBSD) remain their own
promotion sub-PRs (campaign §6); the optional true tracer stays a future
replacement.

The single load-bearing risk to watch during implementation (§9) means the
wrapper's real-build denial mapping (§2) deserves its own focused fixture, but
that is a test within this sub-PR, not a decomposition.

---

## 9. The single biggest security risk

**Under-exercise laundering: build+link reachability is weaker than runtime
intent, so a native capability a wrapper reaches only when *called* with real
data reads as "unused" — and could be flagged declared-but-unused, pushing the
author to drop the declaration, after which the shipped artifact carries the
capability *undeclared*.** The mitigations, all already structural, must stay
load-bearing: (i) the declared-but-unused reject fires only when the static
wrapper scan *also* agrees the axis is unreached (`reconcile_native` §2 +
`WrapperScan`, which reads an unenumerable wrapper as reaching *every* tightenable
axis, `audit_native.rs:475`); (ii) the runtime jail (ADR 0040) still confines the
shipped artifact to the *declared* set at `ipe run`, so an undeclared-but-present
axis is denied at run regardless; (iii) the honest surface never claims more than
build+link coverage (§4). The residual: this harness's `Clean` is a fact about
*building and linking* the native surface, not about every runtime path — and
that boundary must be re-audited if a future sub-PR ever lets the probe invoke
wrappers with real inputs (which would re-introduce both the fabrication problem
and unbounded author-code execution).
