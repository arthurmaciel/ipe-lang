# Prior-art sweep — ancestor `../sky/runtime-rust` vs current campaign (2026-07-09)

> Input for the Fable classification/spec-writing swarm (Phase 2 of the
> 2026-07-09 hardening campaign). Before writing an implementation spec for
> any in-scope backlog item, check here first — several already have a
> working reference implementation in the ancestor Rust runtime.
> Scope researched: Sweep-front, Tier-1, Security tier, AUD-08/09, Rename
> (#59), Non-blocking hardening. Tier-3/Tier-2 excluded (deferred).

## Adopt-worthy (port these, don't redesign from scratch)

1. **CSRF middleware (#63)** — `../sky/runtime-rust/src/sky_runtime/live/csrf.rs`
   (whole file, ~230 lines). Near-complete double-submit implementation:
   `__Host-sky_csrf` cookie (falls back to plain `__sky_csrf` over HTTP dev,
   since `__Host-` mandates Secure), `SameSite=Strict` (or `None; Secure`
   under iframe/frame-ancestors), 32-byte CSPRNG token, **constant-time
   compare via `subtle::ConstantTimeEq`** (`:211-214`), header `X-Sky-Csrf`
   checked only on POST/PUT/DELETE/PATCH, exempt-path list for SSE/
   observability/console, optional `SKY_LIVE_CSRF_ORIGIN_CHECK=on`.
   **Caveat:** `../sky/runtime-rust/docs/CODE-REVIEW.md:986` (2026-06-18)
   flagged that at audit time the module wasn't yet wired into
   `serve_live`'s actual request path — verify current wiring in that repo
   before assuming end-to-end coverage; the module itself is directly
   portable regardless.
2. **i64::MIN abs saturation (AUD-09)** — `math.rs:38-40`:
   `x.checked_abs().unwrap_or(i64::MAX)`, commented "Saturates i64::MIN to
   i64::MAX (no-panic rule: -i64::MIN is not representable)." Trivial direct
   port for `Math.abs`/`Basics.abs`/`List.range`.
3. **Time lossy-cast fix pattern (AUD-09)** — `time.rs:260-268`
   (`time_days_in_month`) already does the correct `i32::try_from(year)` +
   Err→0-fallback idiom, with comment: "Parse year into chrono's i32 domain
   rather than truncating: a lossy cast on a large caller Int would wrap to a
   valid band → wrong day count." Applied inconsistently in that same file
   (`is_leap_year`/`from_parts` still do bare `as i32`) — port the pattern to
   all three call sites, in both repos.
4. **HTML escape sink-splitting (AUD-09)** — `html.rs:417-433` deliberately
   splits `escape_text` (escapes `& < > '` for text nodes) from `escape_attr`
   (`escape_text(t).replace('"', "&#34;")`, matching Go's `html.EscapeString`
   byte-for-byte) for attribute-value sinks. If the new repo's single
   `escape_text` serves both sink types, the correct fix is this two-function
   split, not just adding `"` to the one function.
5. **bcrypt spawn_blocking (#129)** — `auth.rs:248,307,323` wraps bcrypt
   hash+verify in `tokio::task::spawn_blocking` ("CPU-bound + blocking →
   blocking pool"). Directly reusable pattern — port it, then apply the same
   pattern to compression/file kernels, which never got it in either repo
   (see "Inherited, no prior art" below).
6. **SQL identifier validation discipline (#61)** — `db.rs:1059`
   `valid_sql_ident` (ASCII alnum+`_`+`.` only, rejects empty, explicit
   "parse-don't-validate" comment) gates dynamic column names in
   `db_insert_fields`/`db_update_fields`/`db_insert_fields_returning`; all
   *values* stay positional-bound (`?`), never interpolated. Not a full
   `SqlFragment` newtype but a solid validation layer to build the newtype on
   top of rather than starting blank.

## Inherited bugs, no prior art (both repos need the same new fix)

- `SqlNull` text-typed NULL vs Postgres — `db.rs:1637-1671`, self-documented
  simplification ("binds as NULL regardless of the witness type"), not fixed.
- Session cookie `Secure` ENV-gated not TLS-gated — `live/csrf.rs:70` +
  `live/mod.rs:798-827` carries a comment naming the exact gap (ENV-gated,
  not request-scoped; a TLS-terminating proxy in front of a dev process still
  gets a non-Secure cookie). `docs/CODE-REVIEW.md:986` flags it unresolved.
  Ready-made problem statement, no fix — the missing piece is a
  request-scoped `X-Forwarded-Proto`/URI-scheme check.
- `Io.readLine` unbounded — `io.rs:12-20`, plain `stdin().read_line()`.
- `gunzip` first-member-only — `compression.rs:44-80`, `GzDecoder` not
  `MultiGzDecoder`. Compression/file kernels also lack `spawn_blocking`
  (companion gap to #129 above — never solved either side).
- Http header-case parity (#33) — `http_client.rs:253-279`, relies on
  `reqwest`/`http` crate defaults (`HeaderName::as_str()` always lowercases),
  no Go Title-Case normalization layer.

## Intentional divergence / inconclusive

- Postgres driver reachability — OLD repo's `config.rs` is an explicit stub
  for standalone-crate testing; the real per-driver logic is generated by the
  Haskell `Project.hs`, not visible in this file. Not a usable comparison
  point either way.

## No counterpart (confirmed, skip re-checking these)

- Inference cluster #2 (untyped top-level binding), AUD-08 (name-collision
  guard), #59 (rename) — OLD repo's frontend was Haskell; no Rust-side
  equivalent exists to compare against.
- #44 (opaque `Secret` type) — zero wrapper types in OLD repo either; every
  secret is a bare `String`. Fresh design item on both sides.
- #105 (Std.Css hardening) — no `css.rs` / `Std.Css` file exists in OLD repo
  at all. Greenfield both sides.
- #32 (Task arity-3 ICE), #122 (Cli.program separator bug), #53 (typed-token
  emit backend) — structurally different surfaces in OLD repo (Haskell-driven
  codegen for #53; no matching combinator/file for #32/#122). Not portable,
  though OLD's `CODE-REVIEW.md` "type-checks-but-cargo-fails" entries are
  corroborating evidence for why #53's typed-AST rewrite is worth doing.
- "Self-oracle" / "db-without-live build" (#34 sub-items) — no OLD-repo
  precedent; likely new-repo-specific test-infra concerns, not a runtime gap.

## Method note

Full search was scoped to `../sky/runtime-rust/src/sky_runtime/` plus its
`docs/CODE-REVIEW.md` and `docs/` divergence notes; grepped by function/file
name matching the new repo's `runtime/src/sky_runtime/` layout (the two
runtimes share close-to-identical file names — `db.rs`, `auth.rs`, `jwt.rs`,
`compression.rs`, `time.rs`, `html.rs`, `config.rs`, `live/*.rs` — since the
new repo's runtime crate is a direct descendant of the old one). Compiler/
codegen-side items were excluded per scope (OLD repo's frontend is Haskell,
not comparable).
