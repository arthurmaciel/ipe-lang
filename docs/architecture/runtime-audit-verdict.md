# ipê runtime — full security/soundness audit verdict

**Date:** 2026-06-30  ·  **Scope:** 100% of production runtime (75 modules + `lib.rs` + `client.js`, ~38k lines)  ·  **Method:** independent fresh-eyes review per module group under PRINCIPLES order (Security → Correctness → Soundness → Efficiency), with explicit focus on *make-invalid-states-unrepresentable*.

## Fork decision: `runtime-sound-proceed`

Fix-in-place across the board; **no group requires from-scratch reimplementation**; no foundations cascade. All Phase 1–3 fixes land before M5→M6→FFI backend wiring.

- **Reimplement from scratch:** — none —
- **Acceptable as-is:** webview, crypto-jwt
- **Fix-in-place (23):** foundations, local-effects, http, db, pubsub-ws, server, html-render, live-core, live-client-js, live-session-sec, live-console-proxy, auth-email, ffi, json-config, live-hub-obs, tui-layout, tui-rest, ui, text-stdlib, collections, numeric, bytes-codec, telemetry

### `unsafe` summary

Exactly ONE unsafe block exists across all 25 groups: console_proxy.rs:161, cmd.pre_exec(|| libc::prctl(PR_SET_PDEATHSIG, SIGTERM)) — and it is correctly justified. pre_exec is unsafe because the closure runs post-fork/pre-exec where only async-signal-safe ops are legal; the closure calls only libc::prctl (async-signal-safe), allocates nothing, takes no locks, returns Ok, and carries an accurate SAFETY comment with an ABI-correct c_ulong argument. It is the parent-death orphan-reaper defense and is not removable without losing it. Every other foundation, effect, http, db, live, ui, tui, numeric, codec, and telemetry file is unsafe-free (the crate is not under #![forbid(unsafe_code)], but the audited files add no unsafe). Several near-panic sites were found and are guarded or only theoretically reachable (saturating/checked arithmetic, poison-tolerant locks, .get() over raw indexing, ZST-only usize→i64 wraps); the only reachable-from-well-typed-Sky panic vectors are the two ffi_polyfills panics (need a compile-time codegen guard upstream), tui-layout fr_total usize-sum overflow → str::repeat panic, and json_enc_encode unbounded indent repeat — all fixable in place.

### Top critical findings (must-fix-first)

1. CRITICAL XSS — html-render runtime/src/sky_runtime/live/diff.rs: diff_attrs/diff_events (L145-176,184-221) copy attribute names/values/event-keys verbatim into Patch.attrs (serialized to SSE, applied by client.js setAttribute) with NO name gate or URL-scheme gate, bypassing every render_into_ctx XSS gate. Any Ipe.Live app is safe on first paint but XSS-vulnerable on the next SSE update of a URL/attr (attacker controls only the value). Fix: route diff sink through the SAME promoted html.rs policy fns + carry SafeAttrName/SafeAttrValue in Patch.attrs.
2. CRITICAL eval sink — live-client-js runtime/src/sky_runtime/live/client.js:966: __skyRunEvals runs new Function(data-sky-eval)() on every full-body patch (called from __skyPatch L376), a CSP-incompatible DOM-XSS amplifier that defeats the C9 script-revival hardening and contradicts CLAUDE.md (data-sky-eval forbidden; __skyRunPaths is the shipped replacement). Fix: delete __skyRunEvals and its call site.
3. HIGH UB — local-effects runtime/src/sky_runtime/file.rs:12 (+ core.rs:104): IPE_FILE_READ_MAX is read via raw std::env::var OUTSIDE system.rs's process-global ENV_LOCK (and core.rs:104 writes via raw set_var), so the lock's 'every Ipê path serialised' invariant is false; Task.parallel setenv+readFile is a genuine reader-vs-mutator environ data race = UB. Fix: route ALL crate env access through pub(crate) locked accessors, or snapshot the cap into a OnceLock at startup.
4. HIGH latent SQLi — live-hub-obs runtime/src/sky_runtime/live/hub.rs:447: count_table builds SQL via format!("...FROM {table}") with an unvalidated &str; current callers pass literals but the signature permits any runtime string. Fix: replace table:&str with enum TelemetryTable matched to hardcoded SQL literals.
5. HIGH header injection — telemetry runtime/src/sky_runtime/telemetry.rs:167: IPE_LIVE_FRAME_ANCESTORS is injected raw into the Content-Security-Policy header; a CRLF in the value splits the response (HTTP header injection). Fix: strip CR/LF/NUL before storing in the OnceLock.
6. HIGH latent XSS — ui runtime/src/sky_runtime/ui/element.rs: AttrAttribute(String,String) imposes no name constraint, so Ui.htmlAttribute "data-sky-eval"/"onerror" is well-typed and representable; benign in the TUI renderer today but a direct XSS path the moment a Rust HTML/Live renderer lands. Fix: SafeAttrName newtype rejecting ^on[a-zA-Z], data-sky-eval, data-sky-* directives.
7. HIGH panic/overflow — tui-layout runtime/src/sky_runtime/tui/layout.rs:1800: render_grid_tracked fr_total usize-sum over Fr(i64) values overflows to a tiny divisor → column width ~usize::MAX → str::repeat panic, reachable from a well-typed Ipê program with large Grid.fr N. Fix: clamp each Fr at MAX_CELLS before summing and in the width computation.

## Per-group verdicts (full)

### `foundations` — **fix-in-place**

Audited the six foundation files (lib.rs, mod.rs, core.rs, task.rs, tea.rs, io.rs) under PRINCIPLES priority order. The crate-wide claim holds: ZERO unsafe blocks in any of the six files. The core types (SkyResult, SkyMaybe, SkyCmd, SkySub) are proper sum types that correctly make invalid states unrepresentable — the make-invalid-states-unrepresentable bar the prompt flagged as never-reviewed is actually met at this layer (no both/neither Ok+Err, no Just-without-value, no stringly-typed status). Security posture is strong: foreign-error Debug is redacted to a fixed message + hex correlation id (server-log only), log/terminal injection is closed via scrub_log_controls (plain) and json_escape (JSON), and the HTTP 500 body interpolates only [0-9a-f]. task.rs retry math is fully saturating/clamped with every as-cast provably in-range; the jitter PRNG correctly avoids thread_rng poison panics; block_on maps panics to Err. All casts (x as u8 byte narrowing, ms as u64, delay as u64, scaled.round() as i64) are either guarded or documented FFI parity. Verdict is fix-in-place rather than acceptable-as-is only because of three localized low-severity items: (1) an unguarded set_var panic vector in set_env_default that diverges from the guarded helper used everywhere else (build-time config only, not remote-reachable); (2) the SkyMaybe lenient deserializer's \"Nothing\"-string sentinel allowing attacker-controlled nullification of Maybe String form fields; (3) an unbounded ticker mpsc channel in the Cli/Tui loop. None are critical, none require reimplementation, the security model is sound and patchable in place. Edition is 2021, so set_var is a safe fn (not the 2024 unsafe form).

**Security findings:**
- **[low]** `runtime/src/sky_runtime/core.rs` — SkyMaybe custom Deserialize (visit_str/visit_string) treats the bare string "Nothing" as the Nothing variant, not Just("Nothing"). For a Ipe.Live form/JSON field typed Maybe String, an attacker can submit the literal value "Nothing" to coerce the field to Nothing instead of a present value. If app logic branches on Just/Nothing for authorization, skip-update, or default-substitution, this is an attacker-controllable nullification of a string field. Documented as a trade-off but reachable from untrusted form data.
  - *Fix:* Disambiguate by decode context: use the strict externally-tagged repr ({"Just":v}/"Nothing") for session-store round-trips, and a separate lenient form decoder that never treats a bare "Nothing" string as the unit variant (form Nothing should arrive as absent/null, handled by #[serde(default)]). At minimum, restrict the "Nothing"-string sentinel to non-String inner types.
- **[low]** `runtime/src/sky_runtime/tea.rs` — SubManager/cli_program use an unbounded tokio mpsc channel (unbounded_channel). A Sub.every ticker with a small ms whose downstream update is slower than the tick rate enqueues CliEvent::Msg without backpressure, growing memory without bound. Not directly remote-driven (app-owned subscriptions), so impact is bounded to misconfigured local Cli/Tui apps, but it is an unbounded queue.
  - *Fix:* Use a bounded channel with a sane cap (mirror IPE_LIVE_QUEUE_MAX) and drop-oldest or coalesce duplicate ticker Msgs on a full channel, surfacing a deduped warn — so a fast ticker can never exhaust memory.

**Panic sites:**
- `runtime/src/sky_runtime/core.rs` — set_env_default (line 104) calls std::env::set_var(key, val) without the validity guard its sibling system.rs::locked_set_var applies. std::env::set_var PANICS if key is empty, contains '=' or NUL, or val contains NUL. Inputs are build-time config (internal IPE_* keys + sky.toml-derived values), so this is NOT reachable from remote untrusted input — but it runs in generated main() potentially before the panic classifier is installed, and is an unguarded panic vector inconsistent with the carefully-guarded set_var elsewhere in the crate.


### `local-effects` — **fix-in-place**

Five local-effects kernels audited. Zero unsafe blocks; the code is unusually disciplined — every fallible op returns SkyResult/SkyMaybe/SkyTask, arithmetic is saturating/wrapping/i128/u128 (random_int full-span, time saturating + i32::try_from year guards), path.rs uses .get() throughout with no raw indexing, and formatting uses std::fmt::write to avoid the to_string()-on-Err panic. No reachable panic sites and no constructible invalid states (these are stateless free functions over primitives, so make-invalid-states-unrepresentable has no surface here). Verdict fix-in-place: the design is sound. HEADLINE finding is a real soundness/security hole — system.rs's process-global ENV_LOCK that guards the UB-prone environ block is module-private, and in-scope file.rs:12 (plus out-of-scope core.rs:104) accesses environ raw and unsynchronised, so the lock's 'every Sky path is serialised' invariant is false; a Task.parallel setenv+readFile is a genuine reader-vs-mutator data race. Secondary: file_read_file_bytes silently truncates oversized files instead of erroring (data-integrity divergence). Low correctness notes (not in arrays): time_is_leap_year uses a truncating `y as i32` where siblings use try_from; system_setenv returns Ok on a no-op'd invalid key (signature lacks From<String> to Err). Recommend the env-lock fix be applied crate-wide, not just file.rs, since the same raw-access pattern recurs in config_decode/compression/db/core.

**Security findings:**
- **[high]** `runtime/src/sky_runtime/file.rs` — file_read_ceiling (line 12), reachable from the File.readFile Task, reads IPE_FILE_READ_MAX via raw std::env::var OUTSIDE system.rs's ENV_LOCK. That RwLock exists specifically because std::env::set_var racing a std::env::var reader is a data race / use-after-free on the C environ block (std + POSIX contract, the reason Rust 2024 made set_var unsafe). system.rs's comment claims 'every Ipê path is now serialised', but ENV_LOCK and its accessors are module-private, so this read is unsynchronised. Under Task.parallel a System.setenv (write lock) + File.readFile (this unlocked read) is a genuine reader-vs-mutator environ race = UB. core.rs:104 compounds it with a raw set_var that bypasses the write lock entirely (second mutator path).
  - *Fix:* Promote read_env_var/locked_set_var/locked_remove_var in system.rs to pub(crate) and route ALL crate env access through them (file_read_ceiling, core.rs:104 set_var, config_decode, compression, db), OR read IPE_FILE_READ_MAX once into a OnceLock<u64> at process start so no per-call environ read races a mutator.
- **[medium]** `runtime/src/sky_runtime/file.rs` — file_read_file_bytes (lines 126-145) does take(10 MiB).read_to_end and returns Ok with the truncated prefix when the file exceeds the cap — silent partial-data success. Sibling readFile/readFileLimit return Err on exceed. A caller reading a binary blob or config larger than 10 MiB silently receives incomplete data with no signal, a data-integrity divergence from the documented Go-parity contract and from the other read kernels.
  - *Fix:* Stat the file (f.metadata().len()) or compare bytes-read against DEFAULT_CAP and return Err('file exceeds N-byte limit ...') on exceed, mirroring file_read_file_limit, rather than silently truncating.


### `http` — **fix-in-place**

Audited http_client.rs, http_stream.rs, ssrf.rs under PRINCIPLES priority order. No unsafe blocks (crate is not forbid(unsafe) but these files contain none). No reachable panic sites: ssrf.rs uses total array/slice destructuring (not indexing) and masked `>>`/`& 0xff` casts; the mutex locks use `unwrap_or_else(|e| e.into_inner())` (poison-safe); the only `.unwrap()` calls are in #[cfg(test)] modules; `as u64`/`as usize` casts are bounded by prior `> 0`/`.max(0)` guards; `it.next().unwrap_or(\"\")` in parse_query is total. The SSRF design is solid: DNS-rebind TOCTOU is closed by resolve_to_addrs pinning + the DenyPrivateResolver vetting every hop, IPv6 NAT64/6to4/v4-mapped/v4-compat embedded-private decoding is covered, and the extra reserved ranges (CGNAT 100.64/10, 240/4, etc.) are matched by octet with boundary tests. Resource exhaustion is bounded: 100 MiB incremental body cap (gzip-bomb-safe), 1024-stream registry with oldest-eviction, monotonic never-zero stream ids. Real issues are localized, not structural: (1) the buffered client leaks raw reqwest errors + req.url to the Sky side, bypassing the B8 redaction (sky_error_from_foreign) that the streaming sibling enforces — a secret-leak inconsistency; (2) SSRF guard is opt-in/off-by-default, so the safe outcome is not the default in production; (3) http_stream_open silently downgrades an invalid method to GET (unwrap_or(Method::GET)) where do_request errors — a correctness/parity divergence; (4) the FFI-bridge records keep method stringly-typed and status as bare i64 with pub fields. None warrant reimplementation — verdict fix-in-place with the targeted patches above (HARDEN, not BLOCK). Note: finding #3 is recorded in the summary rather than a separate array since the schema has no correctness bucket — fix: mirror do_request's `Method::from_bytes(...) => Err(...)` in http_stream_open instead of unwrap_or(GET).

**Security findings:**
- **[medium]** `runtime/src/sky_runtime/http_client.rs` — Foreign-error redaction (the project's B8 two-level pattern via sky_error_from_foreign) is applied in the sibling http_stream.rs (lines 121, 184, 264) but NOT in the buffered client. do_request returns the raw reqwest transport error verbatim to the Sky side: line 262 `format!("http: request to {} failed: {}", req.url, e)` and read_body_capped line 328 `format!("http: reading body failed: {}", e)` (and line 244 client-build error). A reqwest/hyper error Display can echo the request URL, redirect target, and resolved address; req.url itself can carry userinfo or a query-string API key. Per core.rs B8, this detail is exactly what must go to the server log under a correlation id, never into the Sky-visible message. The buffered path defeats the redaction the streaming path enforces.
  - *Fix:* Route the send error (262) and body-read error (328) through sky_error_from_foreign(e) like http_stream.rs does, so Ipê sees only `external operation failed (ref <id>)` and the raw detail (incl. req.url) is logged server-side. Do not interpolate req.url into the Ipê-visible string; if a stable surface is wanted, keep `req.url` only in the server-log line.
- **[medium]** `runtime/src/sky_runtime/ssrf.rs` — The entire SSRF guard (deny-private, metadata-endpoint blocking incl. 169.254.169.254, DNS-rebind pinning) is gated behind IPE_HTTP_DENY_PRIVATE and is OFF by default (ssrf_deny_private_enabled returns false when unset). PRINCIPLES #1 requires the safe outcome to be the only reachable one for untrusted input; a production deployment that forgets to set the env var has Http.get/post/request/stream and the WS client fully exposed to SSRF against cloud metadata and internal services. The default favors dev-localhost convenience over the secure default.
  - *Fix:* Make the guard default-ON in production: tie the default to the existing ENV/IPE_ENV production gate (dev/development/local => off, anything else => on) so IPE_HTTP_DENY_PRIVATE need only be set to OPT OUT, not opt in. At minimum emit a one-time warn log at first outbound request when the guard is off in a production env.

**Invalid-state violations:**
- **[low]** `runtime/src/sky_runtime/http_client.rs` — HttpRequest.method is a bare pub String (a one-of-N HTTP method modeled stringly) and HttpResponse.status is a bare i64. All fields are pub for struct-literal construction across the FFI bridge, so invalid states are constructible: a method like "" or "GET\r\nHost:" or a negative/absurd status. Validity is only checked downstream (Method::from_bytes at send; status is only ever set internally). This is a deliberate mirror of the Ipê record alias, so it cannot be made a true enum without changing the bridge, but the method is the live trust boundary.
  - *Fix:* Keep the pub-field bridge shape, but treat method as parse-don't-validate: parse req.method into a reqwest::Method once at the boundary of do_request/http_stream_open and reject invalid early (do_request already does this; make it the single validated entry). Document that status is internally-set-only and never trusted from a caller-built record.


### `db` — **fix-in-place**

db.rs is fundamentally sound and secure — verdict fix-in-place, not reimplement. Zero `unsafe` blocks in this file (the crate's lone unsafe is the process-module prctl, not here). No panic vectors reachable from runtime input in production code: poison-safe locks, total decoders (all fallible paths -> Err), saturating `f as i64` casts, fail-closed `Arc::try_unwrap`, NULL-tolerant `try_get` cascades. SQL injection is closed on the safe API: all VALUES are sqlx-bound or routed through the total `bind_sql_param`; identifiers are validated; the RETURNING projection is whitelisted; the single raw-interpolation path (`unsafeFindWhere`) is an explicit, documented escape hatch. The transaction design (task-local single-connection routing, flattened nesting, Transaction-Drop rollback on cancellation, bounded pool/connection caches) is genuinely well-built and DoS-hardened. The actionable gap is soundness-of-design: the newer *Fields* kernels abandoned the `SqlIdent` newtype for a bare `valid_sql_ident` bool predicate (validate-then-trust-stringly) whose `.`-policy silently diverges from the newtype — no live exploit, but exactly the make-invalid-states-unrepresentable regression this audit was told to hunt; collapse both validators into one identifier newtype. Plus two low-severity items: DB-error stringification can leak row values into the returned Error, and empty-WHERE updateFields silently rewrites all rows."

**Security findings:**
- **[low]** `runtime/src/sky_runtime/db.rs` — Row-data / info leak through error stringification. `sky_err` (line 11) does `str_err(&format!("{}", e))` over the full `sqlx::Error`. For driver errors — especially PostgreSQL/MySQL — the Display of a constraint violation embeds column VALUES (e.g. `duplicate key value violates unique constraint ... Key (email)=(victim@example.com) already exists`). Every db kernel funnels DB failures through `sky_err`, so that text lands verbatim in the Ipê `Error` value; if the app surfaces or logs the error (common), private row data leaks. Reachable from ordinary inserts/updates with untrusted values hitting a unique/foreign-key constraint.
  - *Fix:* In `sky_err`, when `e.as_database_error()` is Some, build the message from the structured fields that are safe to expose (SQLSTATE code + a fixed generic phrase, optionally constraint NAME) rather than the full Display which interpolates the offending value. Keep full detail only behind a debug/log-level gate, not in the returned `Error`. Confirm Go-reference parity and record any deliberate divergence per PRINCIPLES #2.
- **[low]** `runtime/src/sky_runtime/db.rs` — `db_update_fields` with an empty `where_cols` list emits `UPDATE <table> SET ... ` with NO WHERE clause, updating EVERY row. It is documented as intentional Go parity, but it is a dangerous default reachable when an app derives the WHERE list from request input and that list comes back empty (filter dropped, missing field) — a silent full-table overwrite. Not an injection, but a wrong-default footgun the caller cannot distinguish from a scoped update.
  - *Fix:* Keep Go parity but make the all-rows update opt-in: when `where_cols` is empty, return `SkyResult::Err("db.updateFields: refusing unscoped UPDATE (no WHERE); pass an explicit condition or a dedicated updateAll kernel")`. If full-table update must stay reachable, expose it through a separate, explicitly-named kernel so the unscoped case is a deliberate type/name choice, not a default.

**Invalid-state violations:**
- **[medium]** `runtime/src/sky_runtime/db.rs` — Two divergent SQL-identifier validators coexist and the newer one abandons the newtype. Older kernels (db_insert_row/db_update_by_id/db_get_by_id/db_find_*) parse names through the `SqlIdent` newtype (struct SqlIdent, parse=[A-Za-z0-9_], constructor-only) so an unvalidated identifier is unrepresentable past the boundary — textbook parse-don't-validate. The newer kernels (build_insert_sql, db_update_fields SET+WHERE cols, db_insert_fields_returning) instead call the bare predicate `valid_sql_ident(&col) -> bool` ([A-Za-z0-9_.] — note it additionally allows `.`) and then interpolate the RAW `String`/`table`/`col` into `format!("... {} ...")`. The validated-ness is not carried in any type: safety rests on every interpolation site remembering to call the predicate first. Every current site does, so there is no live injection (alphanumeric+`_`+`.` cannot break out of the identifier position), but this is the validate-then-trust-stringly shape the audit hunts, and the silent `.`-policy divergence between the two validators is undocumented.
  - *Fix:* Collapse to ONE newtype that carries the proof. Extend `SqlIdent` (or add a sibling `QualifiedIdent`) to admit the qualified `table.col` form, give it the single validating `parse` constructor and an `as_str()`, and route build_insert_sql / db_update_fields (both SET and WHERE columns) / db_insert_fields_returning / db_insert_fields through it instead of `valid_sql_ident`. Delete the bare `valid_sql_ident` bool predicate (or make it private and used only inside `SqlIdent::parse`). Then an interpolation site physically cannot receive an unvalidated identifier, and the `.`-policy is defined in exactly one place. Document why qualified names need `.` while single table/column names do not.


### `pubsub-ws` — **fix-in-place**

Group pubsub-ws audited fully against PRINCIPLES order. No `unsafe` blocks in either file (crate is not under forbid(unsafe_code), but these two modules contain none). No reachable panic sites: all Mutex locks are poison-tolerant (unwrap_or_else(into_inner)), the only downcast rebuilds on the impossible None instead of unwrapping, no [] indexing/slicing, and every int cast is guarded (u16::try_from for close codes, timeout/ping `as u64` only after a >0 check, message-size parse filtered >0). SOUNDNESS of pubsub.rs is strong by design — the broker keeps payload `T` as its real type end-to-end (the one dyn Any is the TypeId-keyed container, correct by construction), buffers are bounded (TOPIC_CAP), zero-receiver topics are pruned, and SESSION_SID is read synchronously before the spawn closure so the recv loop captures the right sid. ws_client.rs is defensive: fail-closed on bad header name/value (echoing only the header NAME), SSRF validate + resolve-pin to close the TOCTOU, bounded cmd mpsc (try_send) + bounded frames broadcast + inbound size cap (worst-case retained memory documented), both stream halves aborted on a wedged Close so a close can never strand an open socket. Findings are localized, hence fix-in-place not reimplement: (1) MEDIUM security — connect error messages interpolate the full URL, leaking any ws://user:pass@host userinfo into logs (the header path already avoids this for values; the URL path is the gap); (2) LOW security/resource — a connect/close race can leak one ws_subscribed HashSet marker that monotonic ids never reclaim; (3) LOW soundness — WsCloseCode::Custom(i64) is a pub bridge enum that can encode a non-canonical/out-of-range close code (no invalid-state representable in practice because ws_close_code is the de-facto sole constructor, but the type permits it). CORRECTNESS note (no schema array; recorded here): because the reader task starts broadcasting at connect but subscriptions attach only when the SubManager materialises them, and broadcast has no replay, server frames pushed in the connect→first-subscribe window are silently dropped — onMessage can miss immediate server-push messages. This appears intentional (mirrors Go's no-replay broadcast and the subscribe-once comment); worth a documented contract note rather than a code change. Recommend the medium URL-redaction fix before release."

**Security findings:**
- **[medium]** `runtime/src/sky_runtime/ws_client.rs` — Connect error messages embed the full caller-supplied URL verbatim (lines 131, 143, 152, 204-207, 246, 251-255: format!("WebSocket.connect {}: ...", url)). WebSocket URLs legitimately carry userinfo (ws://user:password@host/...). ### `telemetry` — **fix-in-place**

Five files reviewed. No unsafe blocks anywhere in the group — clean on that front. All production-path Mutex locks use unwrap_or_else(|p| p.into_inner()) poison-recovery; every unwrap/expect is confined to #[cfg(test)] code.

Two security fixes are required before this code handles untrusted inputs in a multi-tenant deployment: (1) IPE_LIVE_FRAME_ANCESTORS must be CRLF-stripped before injection into the Content-Security-Policy header — a raw env var with \r\n causes HTTP response splitting; (2) json_escape must escape U+2028/U+2029 to match Go's encoding/json default and prevent XSS in HTML-embedded telemetry JSON consumed by the console browser client.

Two make-invalid-states-unrepresentable violations were found (this design was never reviewed under that principle): LogEntry.level is a bare String where an enum of four variants is the correct type; MetricKey.labels is Vec<(String,String)> where &'static str labels would enforce the cardinality-DoS constraint at compile time rather than relying on a documentation comment.

Minor soundness: cache handle counter uses plain i64 arithmetic (debug-panic on overflow); two u128→u64 narrowing as-casts in telemetry and trace (theoretical at hundreds-of-thousands-of-years durations). The cache slot.entries / live count divergence under lazy TTL expiry is a correctness note — the LRU eviction path is unaffected and the behaviour matches the documented Go parity model. The SQLite spill URL is unguarded against ? or # in the path env var. The log_println unsanitized stdout write is intentional Go parity (Go: fmt.Println) — annotate the doc comment to make that explicit.

**Security findings:**
- **[high]** `runtime/src/sky_runtime/telemetry.rs:167-196` — HTTP header injection via IPE_LIVE_FRAME_ANCESTORS: frame_ancestors() reads the env var raw and injects it verbatim into `format!("frame-ancestors {fa}")` which becomes the Content-Security-Policy response header. A CRLF in the env var splits the header line, allowing injection of arbitrary HTTP headers. The OnceLock snapshot prevents TOCTOU but does not sanitize the value.
  - *Fix:* Before storing in the OnceLock, strip CR/LF/NUL: `v.chars().filter(|c| !matches!(c, '\r'|'\n'|'\x00')).collect::<String>()`. Alternatively, validate at startup and panic with a clear diagnostic if the value contains these bytes.
- **[medium]** `runtime/src/sky_runtime/telemetry.rs:570-580` — json_escape() does not escape U+2028 (LINE SEPARATOR) or U+2029 (PARAGRAPH SEPARATOR). Go's encoding/json escapes both by default. The console feeds entries_json()/spans_json() to a browser JS client; U+2028/2029 in a log message break a JS string literal in HTML-embedded JSON contexts (XSS). This is also a Go parity divergence — HMAC-over-JSON signatures diverge for any message containing these codepoints.
  - *Fix:* Add two arms to the match in json_escape: `'\u{2028}' => out.push_str("\\u2028"), '\u{2029}' => out.push_str("\\u2029")`
- **[low]** `runtime/src/sky_runtime/trace.rs:62` — trace_attr writes key and value unsanitized to stderr: `eprintln!("[trace] attr sky.trace.{} = {}", key, value)`. A Ipê app passing user-provided data to Trace.attr can inject fake log lines via embedded newlines. log.rs guards against this with sanitise_log_msg; trace.rs bypasses it. Only reachable when IPE_TRACE is set.
  - *Fix:* Apply sanitise_log_msg (or its equivalent) to both key and value before the eprintln call. Move the helper to telemetry.rs as a pub(crate) utility so both modules share it.

**Invalid-state violations:**
- **[medium]** `runtime/src/sky_runtime/telemetry.rs:23-27` — LogEntry.level is a bare String. Any byte sequence is valid: "", "CRITICAL", "verbose" are all representable and accepted by record_log. The error ring gate (eq_ignore_ascii_case("error")), the Prometheus threshold, and the console JSON all assume a closed 4-value set. A call site passing "err" silently miscounts errors. This was never reviewed under make-invalid-states-unrepresentable.

The four call sites in log.rs already pass string literals — replacing with enum variants is mechanical. The JSON/plain output calls level.to_string().
- **[medium]** `runtime/src/sky_runtime/telemetry.rs:249-262` — MetricKey.labels is Vec<(String,String)> — any string value is a valid label, including session IDs, raw request paths, user IDs. Currently all call sites pass &[] — one wrong future call breaks this.
  - *Fix:* Change labels in MetricKey and norm_labels to Vec<(&'static str, &'static str)>. Static string literals are bounded at compile time by construction.   - *Fix:* Replace `g.0 += 1` with `g.0 = g.0.saturating_add(1)`. Document that saturation at i64::MAX means no new caches can be allocated (effectively a process restart is needed at that extreme, which is acceptable).
