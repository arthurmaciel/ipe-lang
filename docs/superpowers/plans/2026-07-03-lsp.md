## Goal

Ship a JSON-RPC-over-stdio language server (`ipe lsp`) that is a *second consumer*
of the one salsa query graph — never a divergent second analyzer — delivering
best-in-class DX: diagnostics that link their `explain` page, hover that shows the
inferred type **plus** a teaching snippet, go-to-def / find-refs / rename /
semantic tokens / signature help, DCE-aware `Ipe.*` auto-import, TEA scaffolding,
and the headline differentiator: **type-directed completion** that queries the
expected type from HM inference and offers only type-compatible candidates, ranked
exact > unifiable > in-scope. Every feature is served from a cached per-module
salsa query so hover/completion are keystroke-fast, cancelled on the next edit, and
**can never show a stale or wrong type** (the clean-vs-incremental parity gate from
Tier-3 #3 Task 18 is the guard).

## Global Constraints

1. **PRINCIPLES order (hard, from both specs):**
   `security > correctness > soundness > efficiency > completeness > readability`.
   For the LSP the sharpest edge is **correctness > efficiency**: a fast approximate
   answer that disagrees with `ipe`, or a stale hover delivered against text the
   user already changed, is a correctness violation and outranks any latency win.
   The responsiveness mechanism is salsa incrementality + cancellation, **never** a
   lying-but-fast shadow analyzer (forecloses hazard L-A). When a feature cannot be
   made both fast and sound on a backend, gate it by verification-cost class (ship
   it when salsa makes it sound-and-fast), do not ship a fast-and-wrong version.

2. **Two fundamental rules, applied to the server:**
   - **PARSE, DON'T VALIDATE** — the untrusted boundary is (a) LSP wire JSON and
     (b) half-typed editor buffers. JSON-RPC params are parsed **once** into typed
     request structs at the `sky_lsp_server` boundary; positions are parsed from
     UTF-16 `Position` into a typed byte `Span` through **one** property-tested
     `ropey`-backed converter (hazard L-I) and never re-derived ad hoc. A malformed
     buffer is a *first-class partial value* (`ParseResult` with typed error nodes),
     not an exception. Completion candidate classification is a closed enum
     (`ExactType | Unifiable | InScopeOnly`) so "no expected type" ≠ "unifies with
     nothing". Filesystem/stdio capability lives **only** in `sky_lsp_server`; the
     query path and feature handlers hold no `std::fs`/`std::env`/`std::io` (INV-1).
   - **MAKE INVALID STATES UNREPRESENTABLE** — a `WorkspaceEdit` is derivable
     **only** from an `Ok(VerifiedEdit)` whose sole constructor round-trips the
     edit's full blast radius through `parse→canonicalize→typecheck(+exhaustiveness)
     →fmt` (Q5 G2); there is no code path from a rejected edit to a surfaced action.
     Walker `match`es carry **no wildcard arm**, so a new AST variant is a *compile
     error* until every walker gets its arm (Q5 G4). Speculative unification during
     completion ranking runs on a **cloned/scratch** UF arena that cannot mutate the
     memoized `typecheck` result other queries read (the soundness core of the
     headline feature — see the query design below).

3. **Non-negotiables carried from CLAUDE.md / repo:** the workspace
   `deny(unwrap_used, panic, indexing_slicing, unreachable)` lints stay green on all
   new crates (defense-in-depth over G3's `catch_unwind`); every synthesized edit is
   built from structured typed-IR/AST, **never** string-concatenation of
   program-derived data (mirrors the emit-time injection foreclosure, hazard L-B);
   the LSP executes **no** project code and never triggers FFI introspection off the
   `ipe add` path (an FFI cache miss hard-refuses, never regenerates — hazard L-N,
   closes the LSP-RCE surface); formatting delegates to the one `Format` crate `ipe
   fmt` uses and must stay idempotent (hazard L-K); every per-request handler is
   latency-budgeted (~3 s ceiling → friendly "request exceeded budget", never hang).

## The headline: type-directed completion — query design

This is the differentiator and the riskiest correctness surface, so its query
contract is designed here before any task references it. Three new salsa queries,
each pure, memoized per `(ModuleId, revision)`, total (never panics on partial
buffers), and — critically — **isolated from the real inference arena**.

### Query A — `expected_type_at(ModuleId, BytePos) -> Option<ExpectedType>`

*What context requires the hole at the cursor to be.* This is the type pushed
**down** onto a region by its surrounding position — a call-argument slot, a
record-field initializer, a list element, a `case`/`if` branch against the scrutinee
/ other branches, an annotated binding's RHS, a `Cmd`/`Sub`/`Element msg` slot. It
is **distinct** from the *inferred* type of a complete expression (`region_types`,
Query in Task 7): at a cursor inside an incomplete expression there may be no
complete expression to infer, but the context still pins what the hole must be.

- **Compiler work (Task 12).** During constraint generation `sky_types` records an
  `ExpectedTypes: Map Region Ty` sidecar alongside `region_types` — the analog of
  the Haskell `LowerCtx` expected-type push-down. When a region is constrained to
  unify with a known expected type `τ`, it is recorded. After solving, `τ` is read
  back resolved through the UF arena; unbound vars survive as wildcards (`α`).
- **Query behavior.** Locate the **smallest enclosing region** whose expected type
  is recorded at `BytePos` (walk the region tree, clamp position to buffer bounds).
  Return `Some(ExpectedType { ty, provenance })` where `provenance` names the slot
  kind (arg-of `f`, field `label`, branch-of `case`) for ranking + hover context, or
  `None` when the position is unconstrained (top-level unannotated binding, module
  head) → completion degrades to scope-only.
- **Totality / soundness.** Pure read of the memoized `typecheck(module)` output;
  no mutation, no `unwrap`, position clamped. `None` is a first-class answer, not a
  failure.

### Query B — `scope_at(ModuleId, BytePos) -> Arc<ScopeSet>`

*What names are visible here, each with its resolved type scheme.* Derived from
`canonicalize(self)` + `resolve_imports(self)` + `kernel_types()`:

- locals bound by enclosing `let` / lambda params / `case` patterns (innermost
  shadowing outermost),
- module top-level bindings + constructors + type-alias record fields,
- imported names **and** the DCE-aware auto-imported `Ipe.*` qualified set (all
  available; not-yet-imported names are carried with an `import_needed` flag so the
  completion handler can attach the lazy `additionalTextEdits` — Q4 / Task 22).

Each `ScopeEntry` carries `{ name, qualifier, scheme: TyScheme, origin: Local |
Module | Imported | AutoImportable }`. Pure over the resolved program; no private
drifting index (forecloses hazard L-D — the "index" **is** derived queries).

### Query C — `unifiable_candidates(ModuleId, BytePos) -> Arc<Vec<RankedCandidate>>`

*The filter + rank.* Consumes `expected_type_at` + `scope_at`. For each `ScopeEntry`
with scheme `σ`:

1. **Instantiate `σ` with fresh vars in a SCRATCH UF arena** — a clone/snapshot of
   the solve arena, or a fresh throwaway arena seeded with the entry's scheme.
   **This scratch arena is never written back.** This is the load-bearing soundness
   invariant: speculative unification during ranking must not mutate the memoized
   `typecheck` result that diagnostics + hover read, or a hover right after a
   completion could show a WRONG type (a direct correctness > efficiency violation).
   Because `unifiable_candidates` is itself a pure salsa query, the scratch work is
   memoized per revision, not repeated per keystroke.
2. **Compute the candidate's offer-type.** For a value, its type. For a function
   `a -> b -> r`, consider both the fully-applied result `r` **and** each partial
   arity (a `(Int -> String)` candidate is `Unifiable` for an expected `Int ->
   String` slot *and* for an expected `String` slot when fully applied). Record which
   arity matched (drives the snippet: offer `f ${1:arg}` vs bare `f`).
3. **Try to unify offer-type with `expected` in the scratch arena**, classify:
   - `ExactType` — heads identical / unifies with no substitution on the expected
     side (a slot expecting `Int` and a candidate of type `Int`, or a constructor of
     exactly the expected ADT). Highest rank.
   - `Unifiable` — unifies under some substitution (expected `List a`, candidate
     `List Int`; expected `α`, any candidate). Middle rank.
   - `InScopeOnly` — no expected type recorded, **or** unification fails. Offered
     **only** when `expected_type_at` returned `None`; when an expected type exists,
     non-unifying candidates are dropped (a slot expecting `Int` MUST NOT suggest a
     `String`). Lowest rank / gated.
4. **Structural candidates from the expected type itself:** if `expected` is a
   record `{ f1 : τ1, … }`, offer its fields (for `record.` access completion); if
   `expected` is a nominal ADT `T`, offer `T`'s constructors; these are `ExactType`.

**Ranking (deterministic, total order):** `ExactType` > `Unifiable` > `InScopeOnly`;
within a class, `origin` proximity (`Local` > `Module` > `Imported` >
`AutoImportable`), then shorter arity-to-fill, then lexicographic name. The LSP
`sortText` is a fixed-width encoding of this key so the client preserves the order.
Ties never resolve nondeterministically (a nondeterministic order would fail the
golden completion test).

**Guardian invariants on this feature (enforced by test):** (i) scratch-arena
isolation — a property test runs `typecheck(m)`, snapshots `region_types`, runs
`unifiable_candidates` at many positions, re-reads `region_types`, asserts
**byte-identical** (speculative unification left no trace); (ii) an expected-`Int`
slot never emits a `String`-typed candidate (headline correctness test); (iii)
totality under fuzzed/truncated buffers (no panic, bounded time).

## Salsa-fit mapping — each feature → the query it consumes

The `sky_db` graph from Tier-3 #3 powers **both** `ipe watch` and the LSP; there is
no second engine. Every handler is a pure fn `(snapshot, position) → payload` over
the `ProgramView` trait; the trait's two backends (`BatchView` v0, `SalsaView` v1)
have **identical signatures** so the swap is backend-only (spec Q1).

| LSP feature | salsa query(ies) consumed | Cost class | Backend |
|---|---|---|---|
| Diagnostics | `parse` ∪ `canonicalize` ∪ `typecheck` (verbatim `Diagnostic`s) | single read, debounced | v0 |
| Hover (type + explain) | `typecheck(m).region_types[region_at(pos)]`; `kernel_types()` for kernel sigs; `explain_page(code)` | single read | v0 |
| Go-to-def / declaration | `resolve_imports(m)` + canonical binding sites | single read | v0 |
| Document symbols | `parse(m)` top-level decls | single read | v0 |
| Formatting | `Format` crate over `parse(m)`, one full-doc `TextEdit` | single read | v0 |
| Semantic tokens | exhaustive AST walker over `parse(m)` (G4) | single read | v0 |
| **Type-directed completion** | `scope_at` + `expected_type_at` + `unifiable_candidates` (queries A/B/C) | read + speculative-unify (memoized) | v0 basic / **salsa full** |
| Signature help | `typecheck(m)` callee signature + active-param index | single read | salsa |
| Inlay hints | `typecheck(m).region_types` (inferred `let`/param types) | single read | salsa |
| Find references | `collect_references` walker over the resolved program | whole-program | salsa |
| Auto-import | canonicaliser export index (salsa query) + `resolve_imports` | whole-program | salsa |
| TEA code actions / quick-fixes | `resolve`/`typecheck` + the `VerifiedEdit` round-trip (parse→canon→typecheck→fmt over the blast radius) | full recheck per invoke | salsa (v0: apply-time-verified) |
| Rename | `prepareRename` gate + `collect_references` + `VerifiedEdit` speculative typecheck | whole-program | salsa |

**Cancellation (shared substrate — Tier-3 #3 Task 25).** Only the main loop mutates
the `Db` (single writer), applying `didOpen/didChange/didClose` in receipt order. A
`set_source_text` bumps the salsa revision, which cancels in-flight read snapshots
via salsa's `Cancelled` unwind; the worker unwinds cleanly and the handler returns
LSP `ContentModified (-32801)`; the client re-requests against new state. A stale
hover/completion **can never** be delivered against text the user already changed
(correctness > efficiency). `$/cancelRequest` cooperatively drops the pull. This is
the *same* cancellation `ipe watch` single-flight consumes — one mechanism, two
drivers (LSP sets inputs from unsaved buffers, watch from disk).

## Fastness strategy — targets and how they are met

- **Warm hover: p50 < 5 ms, p95 < 50 ms.** Hover is a memoized read of
  `typecheck(module).region_types`; a hover right after a diagnostics pass reuses the
  same memoized `typecheck(module)`. Cold (first open of a module) is bounded by a
  single-module typecheck under the `module_interface` firewall (Tier-3 #3 Task 7),
  not a whole-program recheck.
- **Completion: first request < 100 ms, subsequent < 30 ms warm.** `scope_at` /
  `expected_type_at` / `unifiable_candidates` are memoized per `(module, revision)`;
  the expensive step (scratch unification over K candidates) runs once per revision
  and is cached, so re-triggering completion at the same position after a
  non-invalidating action is a pure cache hit. Completion is demand-driven (fired on
  explicit request, not debounced) but fully cancellable.
- **Diagnostics: < 100 ms warm on a body edit**, debounced ~80–150 ms quiescence.
  On a settled edit the loop demands `typecheck` for open documents **and their
  importers** (via the `resolve_imports` reverse edge); the `module_interface`
  firewall keeps a body-only edit from touching importers.
- **`didChange` is O(log n)** (ropey range edit) and byte-equal re-set is an
  input-boundary no-op (auto-save storms don't churn). Reads dispatch to a blocking
  worker pool over `snapshot()`s so a long read never blocks the write loop.
- **Cancellation is the tail-latency guarantee:** the next keystroke cancels the
  in-flight computation rather than letting it complete and be discarded, so p99
  under fast typing stays bounded by the debounce window, not by a full recompute.
- **v0 fallback is correct-but-coarser:** `BatchView` recomputes per-module on
  whole-file settle behind a content-hash cache; slower, never divergent. Features
  whose interactive latency is structurally bad on v0 (find-refs, full
  type-directed completion, verify-on-offer actions) are built behind the trait but
  *enabled* when `SalsaView` delivers sub-100 ms verification.

## Phase 0 — spine (v0 backend, ships diagnostics)

### Task 1 — `sky_lsp_server` crate + `ipe lsp` dispatch + `lsp-server` main loop

**Goal.** A binary that speaks LSP `initialize`/`initialized`/`shutdown`/`exit` over
stdio, negotiates capabilities, and idles — nothing else.

**Test first.** `crates/sky_lsp_server/tests/lifecycle.rs`: drive the server

**Do.** New crate `crates/sky_lsp_server`; add `lsp-server` + `lsp-types` (pinned) to
workspace deps. **Framework decision is locked to `lsp-server`** (spec Q1 / OPEN-3):
the synchronous single-writer main loop owns the (future) salsa `Db`, and salsa's
synchronous `Cancelled`-on-`&mut` cancellation composes with a sync loop —
`tower-lsp`'s async `&self` model fights it (the reason rust-analyzer declined it).
Main loop: receive → match method → dispatch. Add the `ipe lsp` subcommand arm in
`ipe`'s dispatcher that execs this loop. Apply the workspace clippy lint table
(`deny(unwrap_used, panic, indexing_slicing, unreachable)`).

**Verify.** `cargo test -p sky_lsp_server lifecycle`; clippy clean.
**Done when.** Server initializes, advertises Phase-0 capabilities, shuts down clean.

### Task 2 — `ropey` VFS + incremental sync + the UTF-16↔byte mapper (built and tested FIRST)

**Goal.** Open buffers held in a `ropey` rope; `didChange` range edits apply in
O(log n); one centralized, property-tested position converter. Everything downstream
depends on correct offsets (hazard L-I — a wrong conversion lands *every* edit in the
wrong place).

**Test first.** `offset_mapping.rs` **property test**: for random UTF-8 documents
(including astral-plane emoji, CJK, combining marks, CRLF) and random positions,
`byte_of_position(position_of_byte(b)) == b` and vice-versa; LSP UTF-16 code-unit
counting matches (a 👍 is 2 UTF-16 units, 4 bytes, 1 rope char). `vfs_sync.rs`: apply
a scripted sequence of incremental `didChange` range edits, assert the rope equals
the equivalent full-text replacement.

**Do.** `Vfs` maps each `FileId` to the open editor buffer (rope) if present, else
disk bytes; `didClose` reverts to disk (the LSP↔watch reconciliation point — both
feed the *same* salsa inputs, hazard L-G). One module `offset` owns **all** UTF-16↔
byte conversion via ropey's char/utf16 APIs; no ad-hoc arithmetic anywhere else
(PARSE, DON'T VALIDATE the wire position exactly once). Sync kind `INCREMENTAL`.

**Verify.** `cargo test -p sky_lsp_server offset_mapping vfs_sync` (property tests
1e4+ cases green).
**Done when.** Round-trip property holds on all generated inputs; incremental edits
reconstruct the rope exactly.

### Task 3 — The `ProgramView` trait + `BatchView` backend (the backend-swap seam)

**Goal.** The single trait every handler is written against, with the non-incremental
v0 backend that calls the *same* front-end crates (so v0 cannot diverge from `ipe`,
only be slower — hazard L-L).

**Test first.** `batchview_parity.rs`: for a fixture module, `BatchView::diagnostics`
== the diagnostics `ipe` produces for the same source, and
`BatchView::typecheck(m).region_types` is non-empty for a well-typed binding. A
second call with byte-identical content is served from the content-hash memo (assert
via a compute counter).

**Do.** Define `trait ProgramView` exactly per spec Q1: `parse(FileId) ->
Arc<ParseResult>` (never `Err` — typed error nodes + diagnostics as data), `resolve`,
`typecheck` (types + region_types + diagnostics), `diagnostics` (union
parse+canon+type+exhaustiveness), `index`. `BatchView` calls
`sky_parse`/`sky_canon`/`sky_types` behind a `Mutex<Interner>` on whole-file settle,
memoizing per module by content hash. **INV-1: no `std::fs`/`std::env` on the query
path** — the VFS supplies bytes; add the CI grep test (mirrors Tier-3 #3 Task 2).

**Verify.** `cargo test -p sky_lsp_features batchview_parity`; INV-1 grep green.
**Done when.** Trait compiles; `BatchView` reproduces `ipe` diagnostics; memo hits.

### Task 4 — Handler-boundary `catch_unwind` + latency budget + `Cancelled` distinction (G3 layer 3)

**Goal.** No request can crash the server; an over-budget request returns friendly,
never hangs; salsa `Cancelled` is distinguished from a real panic.

**Test first.** `resilience.rs`: a handler that deliberately panics returns an
internal-error response for *that* request and logs a `CompilerBug` line, and the
next request still succeeds (server alive); a handler that exceeds the budget returns
"request exceeded budget"; a `Cancelled` unwind maps to `ContentModified (-32801)`,
not an error. Fuzz gate: feed 1000 random/truncated buffers through
`diagnostics`/`hover`/`completion`, assert **no panic**, bounded time, some response.

**Do.** Wrap each feature handler in `catch_unwind`; classify the payload
(`Cancelled` → `ContentModified`; other → internal error + `CompilerBug` log). Per-
request latency budget (~3 s, the reference server's ceiling). This is defense in
depth **behind** the `deny(panic, unwrap_used, indexing_slicing)` lints and the total
query paths — the lints and `Option`/`Result` returns are the primary guard (G3
layers 1–2); `catch_unwind` catches the unexpected (layer 3).

**Verify.** `cargo test -p sky_lsp_server resilience`; fuzz gate green.
**Done when.** Panics are contained, budget enforced, `Cancelled` distinguished.

### Task 5 — Diagnostics (P0) — compiler `Diagnostic`s verbatim, with explain-page links

**Goal.** Publish the compiler's own diagnostics to the editor, each linking its
`explain` page — highest value, zero new analysis, live immediately.

**Test first.** `diagnostics.rs` (the LSP test harness's first client — see Task 20):
feed a document with a `IPE-T0001` type mismatch; assert `publishDiagnostics` carries
the mismatch at the right range, `severity = Error`, `code = "IPE-T0001"`, and
`codeDescription.href` points at the explain page (or the message footer references
`ipe explain IPE-T0001`). A well-typed document publishes an empty diagnostic set. A
byte-equal re-save republishes nothing new.

**Do.** On settled (debounced ~80–150 ms) `didChange`, demand `diagnostics(FileId)`
for open docs + their importers (`resolve_imports` reverse edge). Map each compiler
`Diagnostic` → LSP `Diagnostic`, carrying `Code`, span→range (via Task 2's mapper),
and `codeDescription` from `explain_page`/`title` (the kind-teacher link). These are
the compiler's values **verbatim** (G1) — the LSP authors no diagnostic. Debounce is
demand-driven, not eager (salsa marks dirty, recomputes on pull).

**Verify.** `cargo test -p sky_lsp_features diagnostics`.
**Done when.** Type/parse/canon/exhaustiveness diagnostics surface with explain links;
empty on clean; no churn on byte-equal save.

## Phase 1 — the alive editor (P1, off existing compiler outputs)

### Task 6 — Semantic tokens — exhaustive walker, no wildcard arm (G4)

**Goal.** Syntax-aware highlighting from an AST walker that makes a new AST variant a
**compile error** until it gets an arm (forecloses hazard L-J, the reference
server's `_ -> []` fragility).

**Test first.** `sem_tokens.rs`: golden snapshot of the semantic-token stream over
the example corpus; a hand-added throwaway AST variant (behind a test cfg) makes the
walker fail to compile (asserted by a `compile_fail` doc-test or CI note). A
compiling-but-wrong arm is caught by the golden snapshot.

**Do.** `sem_tokens` walker `match`es the AST enums with **no `_` arm**;
`#![deny(clippy::wildcard_enum_match_arm)]` on the walker module; CI grep for `_ =>`
in AST matches. This is strictly stronger than the CLAUDE.md grep convention — the
type system enforces "new AST node requires explicit walker arms."

## Phase 4 — TEA scaffolding (the headline #2) behind the `VerifiedEdit` gate

### Task 17 — The `VerifiedEdit` type + blast-radius round-trip gate (G2 — build first)

**Goal.** Make "offer an action that breaks the build" **unrepresentable**: a
`WorkspaceEdit` is derivable only from an `Ok(VerifiedEdit)` whose sole constructor
round-trips the edit's **full blast radius** through parse→canon→typecheck
(+exhaustiveness)→fmt.

**Test first.** `verified_edit.rs`: a structurally-valid edit that type-checks over its
closure yields `Ok(VerifiedEdit)` → a `WorkspaceEdit`; an edit that breaks a
**downstream importer** (e.g. changes a module_interface a consumer depends on) yields
`Err`, and there is **no** way to build a `WorkspaceEdit` from it (type-level — assert
by the absence of any public constructor). **fmt-preservation test:** for every
`VerifiedEdit`, the post-fmt artifact parses to the same canonical AST and produces the
same `typecheck` result as the checked pre-fmt artifact; a second fmt pass is
byte-identical (idempotence, L-K). Compiler-sourced fixes carry their `Applicability`
(`MachineApplicable` → preferred; `HasPlaceholders` → snippet; `MaybeIncorrect` →
non-preferred).

**Do.** `VerifiedEdit(WorkspaceEdit)` newtype; private ctor runs the round-trip over
**every file the edit's `changes`/`documentChanges` touch PLUS every importer of any
module whose `module_interface` the edit alters** (reached via the `resolve_imports`
reverse edge). Body-only edits (unchanged interface) collapse to the single edited
module (empty importer set) so the common case stays cheap. Returns `Err` (never panics
in release; debug panic is a test tripwire only) if any stage is unclean in any
touched-or-importing module. **Verify-timing per backend:** salsa → verify-on-offer
(unsound actions hidden); v0 batch → verify-on-apply (refuse-with-message, spec OPEN-2).

**Verify.** `cargo test -p sky_lsp_tea verified_edit`.
**Done when.** Only round-trip-clean edits become `WorkspaceEdit`s; blast radius covers
importers; fmt-preservation asserted.

### Task 18 — TEA snippet catalog (golden-tested, two type-safety classes)

**Goal.** The fixed, reviewed snippet catalog (`tea-app`/`tea-tui`/`tea-webview`/
`tea-worker`/`msg`/`update-arm`/`sub`/`cmd-perform`/`handler`/`route`), each classified
**self-contained/type-clean** vs **fragment/parse+fmt-clean-only** and asserted at its
own bar (hazard L-M — never over-claim a fragment as a type guarantee).

**Test first.** `snippets.rs` golden: each self-contained snippet's default-filled
expansion **parses, formats, and type-checks** standalone (`tea-app`, `tea-tui`,
`tea-webview`, `tea-worker`, `msg`, `route`, `handler`); each fragment expansion is
**parse-clean + fmt-clean only** (`update-arm`, `cmd-perform`, `sub` — reference free
names). No fragment is tested at the type bar; no self-contained snippet is under-tested.

**Do.** Ship the catalog as `CompletionItem`s with `insertTextFormat = Snippet`
(`$1`/`${2:default}` tabstops). When a client does not advertise `snippetSupport`, fall
back to offering the same scaffolds as plain-text `WorkspaceEdit` code actions
(universal). Linked tabstops keep a name in sync but do **not** enforce variant↔arm
exhaustiveness — that invariant belongs to Task 19 + the exhaustiveness lint (Task 20).

**Verify.** `cargo test -p sky_lsp_tea snippets`.
**Done when.** Catalog ships; each class green at its own bar; snippet-unsupported
fallback works.

### Task 19 — TEA code actions (program-reading, structured edits, gated)

**Goal.** The flagship transforms — *Add Msg variant + matching update arm* (atomic:
appends `| NewVariant` **and** inserts `NewVariant -> ( model, Cmd.none )` so the post-edit
program type-checks by construction), *Add subscription*, *Scaffold TEA app for this

**Verify.** `cargo test -p sky_lsp_tea code_actions`.

joint; all gated.

### Task 24 — Never-stale-type soundness guard (leans on the Tier-3 #3 parity gate)

**Goal.** Prove the LSP can never show a stale/wrong type. The guarantee is inherited: (a)

**Test first.** `never_stale.rs`: scripted edit sequence against a warm LSP db; after each

**Do.** Wire this as a required CI check paralleling the incremental parity gate. A

**Verify.** `cargo test -p sky_lsp_features never_stale`; CI-required.
**Done when.** Every incremental LSP response equals the cold-db response on every fixture +

## The LSP test harness (built alongside Task 5, used by every feature task)

A single in-process harness `crates/sky_lsp_features/tests/harness.rs`:

- **Input:** a source document (or a multi-module fixture map) + a cursor marker (a `⟨|⟩`
  sentinel stripped to a `BytePos`).
- **Drive:** construct a `ProgramView` (parametric over `BatchView`/`SalsaView` so every
  test runs on both backends — proves L-L parity for free), feed the document as a salsa
  input / VFS buffer, invoke the feature handler at the position.
- **Assert:** the returned LSP payload (completion list + `sortText` order, hover markdown,
  diagnostic set + codes + ranges, `WorkspaceEdit` after applying) against an inline
  expectation or a golden snapshot.

This harness is the testability spine: every feature task above states its assertion in
terms of "feed document + position → assert response," and each runs on both backends so a
`SalsaView`/`BatchView` divergence is a test failure, not a latent bug.
